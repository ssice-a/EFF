# 游戏小更新后 Blender 自动继续导出

2026-10-17。已本地安装并在当前实时工程完成验证；未发布 Release，未更新游戏 DLL 或正式 Mod，未保存 `.blend`。

## 实际问题

本次 11:58 左右的小更新将两层 VFS 身份从 `210FF066...D4FDEF1` 改为 `F714FCE6...B5C797C`。Blender 选择的确实是主工作区 `E:/EIEM_Workspace/index/endfield_assets.eidx`，不是错误的目录。原生编译器在整个安装指纹变化时直接拒绝，用户收到 `source index must describe both installed VFS layers`，没有自动恢复路径。

独立索引副本的增量检查确认 273,608 个 Bundle 中只有两个内容 MD5/长度变化，没有新增或退休；两个 Bundle 的资产/CAB 索引记录分别与原记录逐字节一致，总计仍为 3,982,027 条资产。这与已有角色仍能正常替换的反馈一致，但不能据游戏画面推断未来所有新 PFB 都无需重新发现。

## 实现

- 编译器把“需要更新索引”作为单独异常，输出 `OFFLINE-SOURCE-INDEX-STALE` 并返回 3。其他解析/作者/构建错误不冒充需要更新。
- Blender 收到这个明确状态后，在同一作者暂存结果上自动增量更新索引，再执行一次原编译命令。只允许一次重试；刷新失败或游戏继续变化时保留上一发布，避免循环或使用旧记录冒险提交。
- `tools/EFF.SourceIndex` 是插件自带的独立离线工具。链接 AnimeStudio 现有的 VFS、逐 Bundle 内容缓存、解析和索引发布源码，使用相同 parser identity、工作区锁、完整性核对与检查点。未变记录复用，变化/新增包解析，退休包移除。没有复制一套新规则，也不启动 AnimeStudio UI。
- 工具只更新原工作区索引；不重新解包作者源文件，不写 Blender 工程、游戏 Mod 或游戏资源。因此可在来源读锁内运行，不会与源包刷新互相等待。
- 正常游戏基线未变时不调用刷新工具，继续使用已有来源声明和编译缓存。多个 Mod 共用一个工作区索引，第一次更新后不因换 Mod 再次解析相同更新。
- 插件内只新增约 43 MiB 的自带运行环境工具，不附带 830 MB 工作区索引，不要求作者另装 .NET 或运行解包 UI。完整打包脚本和 Blender Release workflow 已纳入该工具及许可证。

保留完整当前索引与来源字节验证。真正不兼容的源 schema、未下载完整的更新或被占用的工作区会给出实际错误；本次修复解决的是“仅全局指纹变化就结束导出”的流程问题。
