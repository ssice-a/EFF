# Blender 网格切换作者流程

当前作者端：Blender 插件 **0.32.0**，按显式选择导出，相机关闭表达游戏隐藏；导出自动拆分面角接缝顶点。
新增形态键的自动控制、稳定变量身份、玩家状态保存和独立材质导入见 [作者状态](author-state-materials.md)。
共享骨架的现行绑定契约见 [骨骼绑定记录](shared-skeleton-binding.md)。原相机/skip 规则不变。
工作区实现与游戏验收状态统一见[文档索引](README.md)。

## 目标与职责

用户只在 Blender 内拆分/编辑网格、组织状态、填写快捷键，然后导出一个 mod。
DLL 继续使用 [条件与按键语法](conditional-keys.md)，不为 Blender 增加另一套运行时语法。
`.blend` 保存切换组/状态/对象关系等语义数据，不保存一份等待字符串替换的 INI。
升级导出器后，旧工程可重新导出；本功能不要求修改 Mesh 二进制格式。

## 最小操作模型

- **切换组**：例如“上衣”“饰品”，各有一个快捷键和初始状态。组之间独立。
- **款式快照**：只记录当前组全部网格在 3D 视图中的眼睛显隐。
- **网格**：一个网格可在同组多个款式中可见；一个对象只能由一个切换组控制，避免两组同时决定其显隐。
- **形态键**：在网格数据属性中独立设置“增大按键”和“减小按键”。增大键始终指向最大值，减小键始终指向最小值；
  DLL 按该控制自己的“变化速度/秒”逐步逼近目标。它不属于款式快照。
- 只处理所选网格，不自动补选同源物体或其他切换状态成员。
- 所选网格的对象相机开关开启时正常导出；关闭（`hide_render=true`）时表达游戏隐藏，
  不导出其网格/材质/贴图/形态键依赖。不在切换组中的相机开启部件保持常显。
- Blender 眼睛/显示器隐藏只用于编辑/预览，不决定游戏显隐。
- 未选中的独立源资源不生成规则。材质与贴图仍按所选可绘制物体的实际依赖导出。

使用实际集合表达结构，Outliner 可见且允许改中文名称：

```text
EFF 切换
  上衣（F6）
    款式 1        ← 当前快照中可见的部件
    款式 2        ← 可为空，也可与款式 1 共享部分部件
    款式 3        ← 另一组显隐组合
  饰品（F7）
    显示          ← 多个饰品部件
    隐藏
```

3D 视图侧栏 N → EFF → 网格切换：

1. 原网格在编辑模式下选面，用 `P → 选中项` 分离，回到物体模式。
2. 选中要一起切换的部件，点击“从所选创建切换组”。插件建立“款式 1/款式 2”；款式 1 记录当前视图，款式 2 初始为整组隐藏。
3. 款式显示为紧凑列表。按住每行左侧手柄上下拖动即可改变游戏内循环顺序；列表顺序同时用于预览、快捷键和简单 UI。
   只调整组内物体的眼睛显隐，点击“+”记录新款式，或用“用当前视图覆盖”更新当前款式；“−”始终删除当前选中款式，至少保留两个。
4. 填组名并录制快捷键。需要删除整组时点击组名右侧的“删除当前组”；这只删除作者切换数据，不删除网格。
5. 另一部分重复操作并使用另一快捷键；左侧圆点指定初始款式，“预览”还原该快照，恢复按钮撤销临时预览。
6. 选择需要导出的全部网格/款式（包括需要游戏隐藏的物体），文件 → 导出 → EFF package。
   只导出当前选择，不会替用户选中其他部件。N → EFF 的“游戏隐藏（相机）”与对象相机图标是同一属性。

不在 Blender 注册游戏的 F6/F7，避免抢占 Blender 自身快捷键；用面板预览状态。
预览临时修改当前视图层显隐，并可恢复预览前的值；不改导出初始款式，也不修改形态键。
全局刷新键仍由游戏的 `plugin/eff.ini` 配置，不复制到每个 mod。

## 导出与 DLL 对接

- 拆分生成的数据块通常保留相同源资源信息，但不再是同一份几何；自动分配唯一导出资源段/文件名。
- 以原 Mesh 选择器分组。同源部件只生成一个命中 Render，避免第一条规则命中使其余部件失效。
- 所选源物体全部相机关闭时，仅生成一个 `handling=skip` 命中 Render，不生成资源文件。
- 同源多部件合并为一个 Mesh，每个部件的每个材质槽对应一个 submesh；命中 Render 直接用 `mesh=` 将其装配到游戏已有 Renderer。
- 单个部件同样原地替换已有 Renderer。Blender 导出器不再生成 `partner.N`，也不创建额外 Renderer。
- 按键切换只通过条件块修改 `submesh_visible.N`。Mesh、材质数组、`bones[]`、`rootBone`、Animator、Physics 和 LOD 归属均保持不变。
- 常显部件没有可见性条件；切换组里的部件按其款式快照生成条件。一个受控合并 Mesh 最多有 32 个 submesh，超过时导出失败。
- F10 磁盘重载负责重新读取和重建变更后的 Mesh、材质与贴图资源；按键路径不承担资源重建。
- 网格切换自动声明 `[Constants]`、`[KeySwitch...] type=cycle`，用 `if/else/endif` 写入 `submesh_visible.N`。
  形态键按键另行生成 `[KeyShape...]`，用 `shape_speed.名称` 声明渐变速度；两类按键不共享状态或动作。
  组/状态显示名仅作注释。
  `[KeySwitch...]` 的值列表严格采用 Blender 款式列表顺序；拖动不会修改各款式已保存的稳定编号。
  相机关闭是无条件隐藏，不为该部件生成 submesh；只有隐藏部件的切换组不生成无效按键。
- F10（或用户设定的刷新键）重新读取 mod 后保留玩家的切换状态；未保存过时使用 Blender 初始状态。
  0.9 导出持久化变量，组和款式编号随 .blend 保存；重排款式不重新编号。删除已保存款式后可用恢复默认值重选。
- 物体范围严格等于所选物体，0.8.1 移除了自动扩展同源和切换组物体的闭包。
  仅保留所选可绘制网格的材质/贴图依赖。导出前显示所选、隐藏、源资源和切换组数量。
- 同源拆分的几块在游戏里仍是一个源 Mesh。导出该源的新几何会整体替换源几何，
  要保留的拆分部件必须一起选中；未选部件不会自动恢复原 Mesh 中的对应部分面。
  这不同于“另一个独立源 Mesh 未选中”，后者不会生成规则。
- `.mesh` 保持独立资源；只输出引用到的修改材质和新增贴图。合并后的材质槽采用新的全局顺序，
  因此导出器会显式写出每个 submesh 对应的材质资源。

示意（导出器自动生成，无需手写）：

```ini
[Constants]
$switch1=0
$switch2=0

[KeySwitch1]
key=F6
type=cycle
$switch1=0,1

[KeySwitch2]
key=F7
type=cycle
$switch2=0,1

[RenderSource1]
asset=OriginalMeshName
mesh=MeshMerged
if $switch1 == 0
    submesh_visible.1=true
else
    submesh_visible.1=false
endif
if $switch2 == 0
    submesh_visible.2=true
else
    submesh_visible.2=false
endif
```

`MeshMerged` 始终挂在原 Renderer 上；按键只清空或恢复目标 submesh 的索引。

## 校验边界

导出前报告：同一对象属于多个切换组、空切换组、快捷键非法/组之间重复、缺失源 Mesh 身份、受控 submesh
超过 32 个。一次无效配置不能先清空已有导出。导入的原骨骼调色板与零权重顶点组仍保留，拆分不重排。
同组多个款式允许共享对象。款式不保存形态键目标；形态键按键在网格数据属性中单独校验和导出。
外部网格必须先完成权重/源资源绑定；本功能不自动猜测骨架映射，也不偷偷合并网格。
同名但来自不同作者包的源资源不自动合并；一次导出若对同一命中资源有多个不相容来源，明确报错。

使用 `.blend` 保留作者工程。新增条件 INI 是运行产物，不承诺把手写的任意 if 程序反编译成集合；离线
静态资源包导入流程不变。用户应重新打开 `.blend` 编辑切换，而不是将产物当作唯一工程文件。

## 验收要求

### DLL 装配契约

导出器生成的每个源 Mesh 规则只修改游戏已有 Renderer。拆分部件在离线导出时合并，运行时不创建、销毁或重新注册 Renderer。
按键验收只需确认目标 submesh 的索引在同一个 Mesh 对象上清空和恢复，并确认 `sharedMesh`、骨骼数组与 rootBone 身份不变。

- 实际 Blender 后台测试：P 分离保留资源身份/蒙皮信息；两组独立切换；状态多网格/空状态；保存重开；
  预览恢复；材质分配；所选资源依赖；重复 ID 自动分配；错误不破坏已有输出。
- 用实际 DLL INI 解析器读取 Blender 导出的文件，并求值各状态，验证常显、隐藏、款式和第二组互不干扰。
- 既有 UV/法线/材质槽与增量导出回归测试继续通过。
- 自动测试不代表大世界/UI/换图原生 Renderer 新建与销毁已验收；部署状态和游戏实测结果单独记录。

## 使用与部署记录

普通 Mod 包导出窗口的“导出按键切换”默认开启。关闭时，导出器使用每个切换组的默认款式，跳过款式与形态键快捷键；形态键数据及滑块声明仍导出。该选项不修改 `.blend` 作者状态。重新导出到已有生成包时，会清理不再引用的自动生成 `ui.lua`。

开发插件目录：`E:\vscode\EFF\tools\Blender`，用 VS Code 打开该目录后运行 **Blender: Start**。
包入口 `__init__.py`、实现 `eiem_blender_addon.py` 和切换逻辑 `eiem_blender_controls.py`
来自独立仓库 [EFF-blender](https://github.com/ssice-a/EIEM-blender)；本仓库的
`tools/Blender` 同时是 EFF-blender 的独立 Git 工作树和 EFF 的固定版本。部署时连同 Physics 模块一起同步，完整清单见
[插件说明](https://github.com/ssice-a/EIEM-blender/blob/main/README.md)。
本机该目录的 `.vscode/settings.json` 开启了 `blender.addon.reloadOnSave`；保存后自动重载，也可手动
运行 **Blender: Reload Addons**。入口在 **文件 → 导入/导出 → EFF package** 和
**3D 视图 → N → EFF → 网格切换**。不要同时运行旁边的单文件副本，以免重复注册。

快速例子：

1. 导入离线 EFF 包，保存 `.blend`；在原网格上用 `P → 选中项` 分离出上衣、饰品，其他部件留下常显。
2. 物体模式选上衣 → **从所选创建切换组** → 名称“上衣”。插件自动分配一个尚未使用的 F 键并生成两个初始款式。
   如需修改，在当前组旁点击**录制按键**，然后直接按键盘按键或 `Ctrl/Shift/Alt` 组合键；Esc 取消。
   可以录制小键盘 `0–9`、`+`、`-`、`*`、`/` 和小数点，也可以与上述修饰键组合。小键盘 Enter
   与普通 Enter 在当前 Windows 热键接口中无法区分，统一记录为 `ENTER`。
3. 选饰品 → 再建“饰品”组。面板持续列出“游戏按键 → 切换组”，无需记忆哪个键属于哪个组。
   多选几个网格一起建组，就会一起显隐。
4. 如需不同款式：先用“所选加入组”补充受控物体；在视图中摆好整组眼睛显隐，再点列表旁的 **+**。
   同一件物体可以在多个款式中可见。按住列表行左侧手柄上下拖动，即可调整快捷键循环顺序。
5. 款式左侧圆点设置初始状态；**预览**显示记录结果，**恢复编辑显隐**恢复预览前的显隐。
   形态键请到网格数据属性 → **EFF 形态键控制**分别录制增大/减小按键并设置变化速度。
6. 回到物体模式，恢复预览后选中需要保留的所有相关网格/款式及隐藏目标 → **导出所选 mod**
   （或文件 → 导出 → EFF package）。文件选择页显示实际所选/隐藏/源资源/切换组数量。
   导出到一个新的 mod 文件夹，不覆盖离线源包。
7. 把文件夹放进 `plugin/mods/`。游戏内 F6 切上衣、F7 切饰品；首次更新 DLL 需重新启动游戏。
   同一个源 Mesh 不要同时启用旧测试 mod 和新导出的 mod，否则现有“第一条命中”规则会竞争。

注意：不要保留一个完整原衣服的副本作为“常显”部件，否则它会遮住显隐变化。
LOD0/LOD1 等仍是不同目标；要在其他 LOD 同步切换，就把相应 LOD 的部件也放入同一状态。
游戏快捷键不要与全局刷新/面板键冲突；Blender 不负责修改其他 mod 或全局快捷键。
`.blend` 必须保留，它才是再次编辑状态与重新生成 INI 的工程源。
