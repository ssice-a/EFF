# 共享索引与旧源包兼容

日期：2026-10-23。状态：已实现共享位置登记、可选索引下载/导入，以及旧源包保留策略。EFF v1.9.0 Release 已提供完整索引附件及 catalog；配套工具为 AnimeStudio v1.8.1、Blender v0.48.0 和 EFF Repair v0.3.0。工程精简索引、丢失源文件自动补齐和旧工程迁移不在本次实现范围内。

## 更新与兼容规则

游戏更新、软件版本变化或安装全局指纹变化，均不能单独证明旧 Mod 或解包源包失效。三个层次分别判断：

| 数据 | 当前判断依据 | 变化后的处理 |
|---|---|---|
| 本机完整索引 | 当前 VFS、索引格式、解析器身份、完整性和失败 Bundle 记录 | 内容未变时重新绑定位置；内容改变时下载/导入匹配包或本地增量构建 |
| 已解包作者源包 | 该包完整的 `bundleInputs` 内容 MD5、长度及依赖闭包 | 相关输入未变则保留；实际改变才在后台刷新 |
| 成品 Mod | DLL 原有的逻辑来源、大小、摘要与协议校验 | 本次不修改 DLL，也不因工具升级统一判旧 Mod 失效 |

老源包没有逐 Bundle 内容证据，或证据为空、损坏、不完整时，自动更新保留源包原样，在工作区 `source-update-skipped.log` 中记录原因。作者仍可从 EFF 菜单选择 **Update previously unpacked EFF resources** 明确刷新。缺少可用 Prefab 锚点的源包也保留，不凭名字猜测来源。

自动源包检查/刷新在资源列表就绪后后台执行，不阻塞浏览和解包。原有事务发布、备份与失败回滚继续生效；软件启动或升级不会仅因版本标签重新提取全部源包。

## 三种索引准备方式

在 AnimeStudio 中打开终末地游戏目录，再选择资源工作区：

1. 先查同一游戏安装已登记且验证可用的工作区，以它作为工作区选择框的默认位置。选择原工作区即可复用，不复制全量索引。用户主动选择其他工作区时尊重该选择。
2. 选定工作区已有有效索引时直接加载；仅 CHK 位置、范围或时间变化而逻辑 Bundle 内容未变时，可重新绑定本机位置。
3. 没有可用索引时显示 **下载预建索引 / 本地构建 / 导入索引包 / 取消**。下载失败或没有匹配包会返回选择界面，不擅自开始全游戏构建。

下载只省去全游戏索引构建。角色、Mesh、材质、贴图和特效资源仍从本机游戏按需提取；完整索引包不包含这些游戏资源。下载、导入和构建在后台执行，状态栏显示进度，**File > Abort** 可取消。VFS 元数据与索引验证/读取也在后台执行。

默认发布源是 `https://api.github.com/repos/ssice-a/EFF/releases/latest`，从 GitHub Release 元数据寻找 `eff-index-catalog.json`。可在准备界面修改源，或通过 `EFF_INDEX_CATALOG` 配置独立索引 Release 的 API 地址/直接 catalog HTTPS 地址，使索引发布不依赖 DLL 更新。

catalog 保持 `EFF_REPAIR_CATALOG/1` 结构，可以列出多份游戏内容的索引。客户端按本机 Bundle 逻辑内容选择匹配项，不按日期盲目选最新文件。下载要求 HTTPS，并核对发布大小与 SHA256；损坏包、取消和失败不会替换原文件。导入继续验证索引结构、完整性及本机 Bundle 内容，重建本机位置绑定。

## 共享目录与登记

默认公共根为 `%LOCALAPPDATA%/EFF/Resources`。三项离线工具使用相同的 `EFF_RESOURCE_ROOT` 环境变量时，可将公共根改到其他磁盘；更改变量不会自动搬移原文件。无需常驻服务，也不扫描磁盘寻找任意 `.eidx`。

```text
EFF/Resources/
  registry.json
  registry.lock
  downloads/
    <game-content-hash>/<package-sha256>.effindex.gz
  installations/
    <installation-path-hash>/workspace/
      index/
        endfield_assets.eidx
        endfield_assets.eidx.bundles
        endfield-index-manifest.json
```

登记文件只保存游戏安装与已有工作区的位置：

```json
{
  "format": "EFF_SHARED_INDEXES/1",
  "entries": [
    {"game": "D:\\Games\\Endfield Game", "workspace": "E:\\EIEM_Workspace"}
  ]
}
```

- 原工作区在原处使用，登记不会复制数百 MB 索引。新用户没有工作区时才默认使用公共目录下按游戏安装隔离的位置。
- 同一安装可登记多个工作区；AnimeStudio 和 Repair 逐个验证，不因第一条登记失效就放弃其余可用位置。登记本身不代表兼容。
- 写登记时使用短跨进程文件锁与原子替换，可取消。登记失败不阻断已经准备好的索引使用。
- 完整工作区需要 `.eidx`、`.eidx.bundles`、`endfield-index-manifest.json` 三件套。不能只复制 `.eidx` 并声称该目录是完整可复用工作区。
- 更新/导入继续使用既有索引锁、暂存与提交规则；本次未另建多代索引目录或后台自动清理服务。

## 各工具如何复用

**AnimeStudio**：打开原游戏与原工作区一次，通过验证后自动登记。GUI 下载、本地构建、导入和 `--import-eff-index` 导入成功均可登记。提取缓存与作者源包仍位于所选工作区，不搬移既有作者工程。

**EFF Repair**：先找同一安装的共享有效工作区，再兼容旧 `%LOCALAPPDATA%/EFF/Repair/workspace`。已有可用索引时跳过重复下载；新下载使用同一压缩包缓存。复用和位置重绑定可能更新索引辅助文件，不编辑该工作区中的作者源包。CLI 显式工作区继续受到尊重。

**Blender**：索引定位顺序为：

1. 显式 `EFF_SOURCE_INDEX`；指定路径不存在则明确报错，不悄悄回退。
2. 作者源包 `source/manifest.json` 中仍然存在的 `sourceIndex`。
3. 同一游戏安装在公共登记文件中的索引。
4. 源包及父级目录中的旧工作区索引。

源清单的旧绝对路径不存在时只作为提示，继续查共享位置和父目录，不修改来源清单或摘要。Blender 这里只发现候选；原生编译器仍验证索引与当前游戏，不能靠注册记录跳过验证。现有编译器明确返回过期状态时，配套 `eff_source_index.exe` 才执行原有的有界增量更新/重试。

Blender 当前仍使用全量索引，不需要每个工程各放一份。它不会自行联网下载索引；缺少索引时在 AnimeStudio 中打开已有工作区，或下载/导入/构建后重试。

## 索引与作者源文件的边界

| 文件/目录 | 用途 | 删除后的影响 |
|---|---|---|
| 工作区 `index/` 三件套 | 资源与消费者查询、本机定位 | 已有成品 Mod 不因此失效；后续制作/修复需重新准备索引 |
| `.eff` / `.efffx` 源包及清单引用的快照/模板 | 提供原生结构、来源身份与编辑输入 | 全量索引不能代替这些字节；需恢复原备份，或重新提取并核对绑定 |
| 作者自制 Mesh、替换贴图等 | 作者内容 | 游戏索引无法恢复，必须备份 |
| 成品 Mod | DLL 运行输入 | 玩家只使用成品时不需要作者全局索引或解包工作区 |

`source-inputs.bin` 是单个 Mod 的来源选择描述，`package-protocol.json` 是工具/读取器能力声明，均不是全量索引。作者源的 `source/streams/` 是原始载荷快照，普通 Blender 导出不读取；是否需要其他文件以对应清单和导出功能为准，不建议为了省空间随意删源包内容。

## 验证及尚未实现的部分

已用合成数据测试下载校验、缓存复用/损坏替换、取消与失败保留原文件；共享登记零复制、不同安装隔离、失效首条/损坏登记回退；跨机器索引导入、本机位置重绑定及增量索引；旧包缺失/损坏/不完整来源记录的自动保留；Blender 工程移动后的共享索引定位、显式配置和来源清单保持。

本次未改游戏 DLL。完整索引附件及 catalog 已发布；工具部署与下载校验结果见本次本机部署记录。下载逻辑测试使用模拟 HTTP，未用真实游戏资源执行完整索引导入。没有用户失败工程与导出日志，不能据此宣称全部旧插件工程都已恢复。

后续可单独推进工程精简索引、缺失游戏来源按需恢复，以及有可靠逻辑身份的旧工程迁移；这些能力目前不能作为用户删除源包的理由。
