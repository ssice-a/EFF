# DLL 通用编译资源接入

2026-10-28 后续开发以[跟随游戏加载的命中与共享资源设计](demand-driven-native-resource-loading.md)为准：PFB 消费者命中移出离线编译，按实际加载局部处理；旧包由 Mod Manager 转换，新 DLL 只读新格式。该新链尚未实现，下文仍描述现有编译资源路径及历史证据。

当前使用独立 Mod 的紧凑运行索引。作者端离线生成读取布局、摘要、展开形态数据、依赖编号、装配和骨骼共享字典；DLL 按需绑定来源并组合实际多写入者。旧编译包读取路径已移除，现有四个 Mod 已更新。新增物理的游戏模拟与物理退出/F10 尚未实机验收。部署、测量范围与实机状态见 [热重载测试](hot-reload-testing.md)。

## 职责

解包工具提供准确来源、原生对象和结构。Blender 及自己的离线编译器生成对象、字段、引用、依赖及目标 Prefab 的完整修改结果。DLL 只回放已编译规则、组合当前 Mod 集合、交给游戏加载并按已适配的游戏生命周期刷新实例。

物理参数、碰撞体形状、骨骼编辑及特效配置不在 DLL 中构建。游戏必须已经识别相应组件和数据；编译包不能创造游戏不存在的脚本实现。新增内容使用同一结构时无须更新 DLL。

## 作者载荷

已有 Mesh / Material / Texture 声明及文件保持兼容。新增通用载荷使用同一 INI：

```ini
[Mod]
format=2
id=Example

[Constants]

[ResourcePhysics]
path=resources/physics.bin
```

`Resource` 开头的声明只指定作者文件。文件沿用 EFFRES 块目录、范围、SHA256 和结构身份；非零 kind 是载荷标识，DLL 不按物理、骨骼或特效种类分派构建器。没有作者 Mesh 的 Mod 也可以读入，但必须提供合法的 `compiled.bin`。只添加 INI 或资源文件不会生成游戏对象。

文件仍属于原 Mod，参与内容契约、修改检测和完整集合事务。目标资源及对象修改在 compiled.bin 中编译确定，不另增用户维护的替换清单。引用作者载荷的 span 与引用原游戏字节的 span 使用相同回放入口。

## 对象组合

单一 Mod 继续直接回放已有编译结果。共享 SerializedFile 根据 pristine 对象和每个 Mod 的修改合并：

- 保留未修改对象及原类型、脚本和 external 注册；按实际 PathID 写入修改、新对象与删除。
- 新原生类型记录从已验证的修改成员取得，保留脚本身份和 TypeTree 字节；追加、去重并重定位类型依赖、脚本索引和脚本 FileID。
- 根据已合并的 external 表重定位对象 PPtr，保留原外部记录顺序与原 GUID。
- 删除与另一 Mod 的对象修改冲突时拒绝；新增 PathID 内容冲突仍拒绝。删除留下本地悬空引用、或修改对象的引用结构无法解码时拒绝，不自动补零。
- 原类型记录不能被另一布局静默覆盖；需要新结构时由编译器提供追加的合法原生类型。原始类型顺序保留。

新类型注册和引用审查只在规则准备时运行。类型表没有扩展的现有 Mod 不进入注册合并路径；没有修改的集合复用准备结果。没有每帧物理解析、场景扫描或作者编译器调用，也没有新增数量/容量限制。

### 多 Mod 的资源数据共享

来源未变化时，多个实际修改者共享一个输入，只合并 SerializedFile 对象记录、类型/引用表与流偏移。`.resS` 数据通过可定位的区间视图引用原游戏流、只读作者文件和已编译字节，不再为每个修改者或最终集合拼出完整像素流。AssetBundle 预加载指针保持紧凑的 12 字节表示，合并区间时不展开成逐指针的递归编辑树。

启动视图共享编译记录自身的不可变字节；F10 隔离版本只在名称位置叠加等宽替换，继续引用启动视图的载荷。所有者随视图保留，最后一个视图释放后回收。虚拟输入长度、映射文件大小、CPU 私有提交量与游戏实际显存占用是不同指标。

游戏来源变化时仍走逻辑路径和语义重放。当前块包中的兼容记录在普通启动时只检查身份与范围，保留已验证压缩快照，在实际请求兼容重放时解码一次；旧包无完整兼容记录时继续报告原有修复要求。本轮没有因为游戏 Mesh 内容变化而新增 Mod 失效条件。

作者编译时，同一 Mod 内的 Texture 声明只有引用同一个作者资源、同一个原生模板且尺寸/mip/采样/色彩设置一致时，才共享原生 Texture2D 与像素载荷。不同作者文件、不同模板和不同 Mod 保持独立。这项去重需要重新编译作者包，不会自动改写既有包中的重复 Texture 对象，也不代表已测得显存节省。

已知余项：兼容记录仍采用完整的修改前后对象，其中 Mesh 整体替换与作者网格资源存在数据重叠；延迟读取降低运行时开销，但尚未消除该离线冗余。普通启动也仍准备全部已编译输入，并非已实现全套按需组合。两项都不能用运行时区间共享的结果代替后续验证。

## 首次加载与 F10

首次加载和 F10 使用同一套对象回放、集合合并及来源匹配。F10 仍沿现有世界模型、模型部件和 UI 模型适配重建，保留动画、武器、音频、临时动作资源、控制及回滚。通用 Mod 没有作者 Renderer 时不强制要求 Mesh marker；仍须满足准确源 Prefab、载荷摘要、引用和游戏加载检查。

本轮没有新增任意场景对象、独立特效管理器或其他加载系统的刷新适配。未来资源加载可以使用通用规则；已加载实例是否能立即刷新，仍取决于实际 owner 的创建、注册和退出流程。没有声称物理 Job 的完整退出屏障已验证，也没有将本轮类型/对象测试当作游戏内物理验收。

## 验证

compiled-mod-set 回归覆盖非三类载荷的 INI/作者描述读取、真实 Author span、两个 Mod 向同一成员添加不同组件类型、共享对象/字段组合、脚本与类型依赖重定位、删除冲突和悬空引用、无 Mesh 的完整编译包读入、集合复用、移除/重新加入及空集合恢复。测试组件和参数是合成数据，不调用物理求解器。

v35/v36 完整事务回归增加无作者 Mesh/marker 的世界与展示刷新；现有游戏安装的三个 Mod 只读组合通过：145 个来源输入、85 个目标 Prefab、10 个共享输入。上述不替代部署后游戏画面验收。

协议声明包含 `compiledObjects`、`resourcePayloads`、`compiledInputView` 与 `compiledRuntimeIndex`。兼容性以实际字段编码判断；当前运行索引布局变化，旧 compiled.bin 需重新导出。没有产品版本门槛。作者载荷及控制继续使用原 INI，不新增用户维护的替换清单。

## 新增骨链的离线编译

选择受新骨链蒙皮的 Mesh 与对应骨架，使用“全部资源”导出。骨架选中时附带该骨架的新增物理组；只选 Mesh 不会默默打包整个骨架的物理。按当前 Mesh 的实际正权重确认组的目标来源，再命中全部引用该来源 Mesh 的 Prefab，不能用材质来源扩展目标。

作者文件保存节点路径和局部 TRS、原生组件模板、参数及碰撞引用；INI 的 ResourcePhysics 声明引用它。离线编译器在每个实际骨架作用域添加新 Transform/GameObject、原生 BeyondBoneCloth 和球/胶囊组件，补齐类型/脚本注册、外部引用与预加载列表。同一骨架的多个 Renderer 不重复生成物理。原有物理、动画和未声明资源保持原字节。新链清空模板的旧拓扑并提供新的 Selection，走游戏已存在的原生构建分支，不能复制原链的预构建数据。

ZFY 的 Silkskirt 左右链离线覆盖 21 个 Prefab，加入 14 个新骨骼、每个模型两个物理组和两个碰撞体；作者物理文件约 281 KB。引用校验、共享骨架去重和通用 DLL 规则回放通过，不代表游戏内摆动、碰撞和连续 F10 的原生工作退出已验收。
