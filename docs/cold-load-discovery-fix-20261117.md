# 冷加载 Mesh 来源发现修正（2026-11-17）

## 问题与证据

前一轮 PID 15304 的实机探针见[测量报告](cold-load-performance-probe-20261117.md)。
10 个 Mod、196 个目标的会话中，未命中的准备调用累计墙钟约 12.87 秒，
其中来源发现约 12.18 秒；这些计时包含子阶段，不能相加。稳定详情页没有继续
发生发现工作，锁等待也接近零，因此本次先处理冷请求的查找范围。

根因在 `PrepareDependencyGroup`：存在无公开路由的 Mesh 子资产时，会把
当前请求的全部原生依赖逐个作为候选容器解析。仅需读取 Mesh/Prefab 的请求
也会进入无关 Material、Texture 和 Shader 包。挂载特效的原生 Mesh 来源核验
有一条相同的全依赖遍历。

回归先在真实 `PrepareDependencyGroup` 调用处加入无关 Texture 依赖，规定
该依赖一旦被打开就失败。原实现命中该失败条件；修正后，目标替换与三轮
删除 Mod/恢复原版均通过，并保持无关依赖读取为零。RED/GREEN 日志位于
`diagnostics/cold-load-fix-20261117/`。

## 实现

- 从实际请求输入、请求依赖范围内的已知目标输入开始。
- 根据真实序列化引用追踪 Mesh、GameObject/Transform 层级、嵌套 Prefab 和
  其他可能承载 Mesh 的组件。未知组件/泛型 Object 引用保持保守追踪。
- Material、Texture、Shader 等终端资源引用不作为 Mesh 查找的扩展入口。
  精确目标容器仍按原有逻辑检查其 preload 区间；不遍历整张 preload 表来
  扩展无关来源。
- 替换和特效挂载来源核验共用 `DependencyGroup` 的遍历。逻辑路径、资产名、
  class 和精确原生引用共同建立身份，名称相同不构成匹配证据。
- 代际缓存只保存已检查输入和原生 CAB 引用关系。Reader、解压缓存与字段布局
  随单次请求结束释放；F10/最终使用者退休仍走原有 SharedScope 生命周期。
- 仅在本次可达查找完整结束后缓存未命中。临时失败和部分结果不成为永久负命中；
  原有确定性检查预算失败策略保留。
- `unity default resources` 和 `unity_builtin_extra` 归 Unity 引擎解析，不参与
  游戏 CAB 来源遍历。首轮实机暴露了这个边界，已补真实引用回归；不把引擎
  内置资源缺少 Bundle 路由误报为 Mod/游戏资源缺失。

查找精确外部 CAB 时，首次仍可能读取依赖包的目录头，以确认其实际来源；
这和把全部依赖的序列化布局、容器与对象都解析一遍不同。游戏原生依赖调度
及其加载/退休由原有共享图保留。

## 验证

新增及扩展的回归覆盖：

- 无公开路由/无 Bundle 提示的本地和跨包 Mesh；目标替换、删除 Mod、连续三轮
  原版恢复，以及旧世界/UI 代际仍可读取。
- 恢复后的 Renderer、原 Shader/Texture、跨包 Mesh 指针和隔离依赖一致。
- 挂载特效的真实 `NativePrefabProof` 调用同样跳过无关依赖，保留精确来源证明。
- 静态/蒙皮 Mesh、外部层级、嵌套 Prefab、未知组件和外部容器根的来源链接；
  材质指针/材质内部引用、无关 preload 不扩展 Mesh 查找。
- 多层引用、循环去重、已知路由种子、重复读取、部分失败重试及新代际隔离。

完整资源热重载、原生随机读取、Mesh 来源证明、入口契约和特效测试通过。
生产构建、二进制检查和实际 LoadLibrary 通过；后者分别从 System32 与游戏
目录运行，确认不依赖开发机当前目录或宿主的 C++ 运行库。生产文件不含本轮
计时、捕帧或特效调试探针。

上述验证证明查找范围和替换/恢复行为，尚不能量化相同 10 Mod 场景的实际提速。
命中后的作者文件不可变快照与局部原生重建也有独立开销，仍需实机场景分别测量。
