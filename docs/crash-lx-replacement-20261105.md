## 可复现缺陷及修正

`EiemNativeRandomAccess::File` 旧实现允许 `FILE_SHARE_WRITE`。保留句柄能维持重命名/删除前的文件对象，但原地覆盖会改变同一对象。`VerifyStable` 仅在准备阶段检查；游戏稍后重新反序列化或延迟读取已发布输入时，旧对象表/字段偏移仍可能读到新文件数据。

生产 `PrepareCarrier` / `StageCarrier` 路径的回归已复现原地覆盖改变既有载体字节。该缺陷与现场反序列化越界相符；dump 未保留完整作者文件内容，不能声称逐字节重建了游戏崩溃当时的混合输入。

修正如下：

- 只在作者 Mesh、Texture2D 骨架、DDS 或 Effect 输入真正打开时冻结文件；通过同一文件对象取得排他写保护后，以 64 KiB 缓冲复制到临时磁盘文件。Windows 在最后一个句柄释放或进程退出时删除快照。
- 旧加载视图持有自己的快照；新目录/新一代能读取替换后的资源。不会全量把 Mod 几何、像素或特效预载进应用内存。操作系统文件缓存及磁盘 I/O 仍有成本，不承诺零开销。
- 控制依赖的 Mesh 元数据不提前复制载荷。首次真正命中时核对文件状态及元数据摘要；不一致时拒绝准备，让既有加载失败/原资源回退路径处理，避免混用描述和载荷。
- 原游戏 CHK/Bundle 范围维持现有按需随机读取，不为整个游戏创建磁盘副本。
- Release 准备脚本加入原生流/原地覆盖回归；已过时的形态 smoke 改用当前可见性与控制发布接口，保留原生显隐及未完成模型快照断言。
