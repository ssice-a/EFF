# 角色包内的特效快速更新（2026-10-20）

用户选择将特效直接追加到 `mods/lx/mod.ini`。旧统一导出把仅选特效一律当作独立包，遇到已有角色包报 `refusing to replace a character Mod`。现根据目标包类型分派：新目录/独立特效包仍按选择生成独立包；已有角色包按特效 ID 合并所选根，不导出挂载人物 Mesh。

操作：只选特效根或发射器，文件 → 导出 → EFF Mod 包，父目录 `plugin/mods`，Mod 文件夹名 `lx`。后续使用同一菜单的 EFF 快速更新所选 Mod；游戏默认 F9。已有挂载 Mesh 的 Part 由精确来源规则和导出部件名匹配，继续跟随显隐/切换。独立子目录导出与角色、特效一起完整导出均保留。

发布通过现有暂存、独立子包边界和可回滚的逐文件事务，只更新变动文件。非选中特效、角色 Mesh/Material/Texture、动画、按键、玩家 state.ini 与子包保留。发布与 F9/F10 共用 Mod 锁，批量构建失败、取消或构建中改参保持上一包。

作者索引原来包含特效载荷的内容证明，直接只改 INI 会使重新启动/F10 拒绝旧引用。因此配套 `eff_resource_pack.exe --update-effects` 先严格比较去除 kind 10 后的原生输入契约，再更新作者图及其证明，保留原生输入、装配、帧和来源记录。旧包的原生字节字典可能意外引用特效中的重复字节：更新前将这些跨度冻结为相同的字面字节，保持输出与重放内容一致；新编译不再用特效载荷作为角色字节字典。原有资源校验、所有哈希和运行读取格式保持。

验证产物位于 `bin/effect-character-update-20261020`：

- 真实 `lx` 无特效角色副本：追加、再加入另一特效、只改首份偏移、挂载到原 Part、全部角色资源/玩家状态/嵌套包保留。
- 真实统一导出：独立包、多选、子节点去重、快速更新、人物与两特效完整编译后再局部更新、失败/取消/构建中修改保留；人物完整导出仍拒绝覆盖独立特效包。
- 原生读取：真实角色的 32 份输入、混合包的 17 份输入与旧包逐一核对输出 SHA256；旧字典迁移后重放成员逐字节一致。启动/F10 组合读取与未修改复用通过，非法角色改动拒绝。
