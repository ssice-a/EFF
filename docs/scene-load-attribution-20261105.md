## 待检验假设

1. **EFF 同步处理或锁等待。** 若主要由它造成，慢加载窗口的 `demand-prepare`（包括锁等待、已准备命中）、代理查询/依赖处理或每帧入口应出现相应长耗时。未命中入口也要测量。
2. **Mod 内容增加引擎加载工作。** 若主要来自替换内容，EFF 准备开销可能很小，但相同场景、相同画质的无 Mod 对照应显著更快；需另查实际网格/贴图/材质的原生反序列化、上传及实例化成本。
3. **电脑内存或磁盘争用。** 若主要来自它，加载窗口应与低可用内存、分页输入、进程读速/盘队列等同时变化；加载结束或游戏退出后的闲置指标不能用于排除它。
4. **游戏自己的加载工作或等待。** 若无 Mod/无插件对照同样慢，且加载期间主要耗时不在插件内，才支持这一方向。不得仅凭 PSO warmup enabled 推断是 Shader 编译。

尚未完成同场景有/无 Mod 的对照。F9/F10 的显隐切换不等于移除替换资源，不能作为干净基线。
