# 物理骨骼与碰撞体：三端设计契约

状态：目标设计。当前实现范围以[文档索引](README.md)、[Physics 运行时重构边界](physics-runtime-redesign.md)、[Physics 作者 v5](physics-authoring-v5.md)及[源作者 v2](physics-authoring-v2.md)为准。
本文描述完整链路要求，不把设计目标、源码草稿或宿主测试当作游戏能力。
沿用[资源替换职责](refactor-resource-replacement.md)、[共享骨架绑定](shared-skeleton-binding.md)和[作者状态](author-state-materials.md)。

## 1. 结论与范围

建议采用：**共享骨架 + 独立 Physics 资源 + Blender 可视化编辑 + 游戏原生物理后端**。

- 借鉴 RE Chain Editor 的链、碰撞体、约束可视化和参数预设交互；不把 RE 的 chain2 当作终末地原生格式。
- 只接入游戏原生物理：先查清 `BeyondDynamicBone` 的数据、构建注册、模拟写回和退出契约，
  再由游戏系统计算；不自写弹簧、Verlet、PBD 求解器，也不提供另一套模拟兜底。
- 先支持原生物理配置的读取/修改，以及在同一角色骨架上增加物理链；整套 Avatar 更换、动画重定向另立范围。
- 自制物理链需要**新增骨骼**，范围包含已有骨骼引用和新节点创建。
  不需要的是“每次 Mesh 隐藏/删除时跟着增删物理骨骼”。骨架节点与物理注册有自己的生命周期，
  由原生物理继续计算；不因当前带权重的 Mesh 数量变成零便删除仍在被原生任务引用的节点。
- 一个角色作者工程共用一个 Armature。一个 Physics 资源可以有多条链和共享碰撞体，不能变成每个 Mesh 一套物理/骨架。
- 运行时按具体模型实例装配。多个角色实例共享不可变配置，但不共享 Transform、模拟粒子、碰撞注册或动画缓冲句柄。

目前有足够接口线索继续实现，但**没有证据证明仅创建几个 Transform 再调用 BuildAndRun，就能让新增骨骼进入游戏自定义蒙皮管线**。
必须先完成第 11 节的原生构建与写回验证。若游戏保留的原生后端不能构建新拓扑，应明确记录限制并重新决策，不能悄悄切成另一种模拟。

## 3. chain2 / RE 编辑器：参考什么，不参考什么

### 3.1 资源组织

查阅 RE Chain Editor 固定提交 `54ed5d41a6360511b4b314c80e9b459032b32688`。
该实现的 chain2 分开记录设置、组/节点、碰撞、风和组间连接；节点有角度约束与骨骼哈希，组引用设置 ID。
这说明 chain2 是物理配置关系图，不是另一份 Mesh 权重或骨架文件。
格式大小存在版本分支，不能把某个版本结构体用于所有 Wilds 包。
依据：[chain2 读写实现](https://github.com/NSACloud/RE-Chain-Editor/blob/54ed5d41a6360511b4b314c80e9b459032b32688/modules/file_re_chain2.py)。

CLSP 是另一个碰撞数据文件，条目有骨骼/配对骨骼哈希、端点和半径字段；不等于 chain2 的全部内容。
该参考实现对部分 box 数据直接跳过、写回零值，所以它不是“所有未知字段无损往返”的模板。
依据：[CLSP 读写实现](https://github.com/NSACloud/RE-Chain-Editor/blob/54ed5d41a6360511b4b314c80e9b459032b32688/modules/file_re_clsp.py)。

上游说明记录了 Wilds chain2 版本更新到 14；仓库已于 2026-04-01 归档。
本次参考固定源码快照，不把旧常量 `VERSION_MHWILDS = 12 # Beta` 解释为当前所有 Wilds 文件的版本。
依据：[上游说明及更新记录](https://github.com/NSACloud/RE-Chain-Editor)。

### 3.2 适合借鉴的编辑方式

- 物理数据单独成集合，链绑定已有 Armature，不把链节点再导入成一套人物骨架。
- 链连线、节点半径、角度锥和碰撞体可见；选中它就能修改对应参数、查看影响范围。
- 球/胶囊显示由参数生成；胶囊端点与锚点联动，不需要用户编辑一堆显示网格顶点。
- 可以从现有物理组复制配置作为预设，再重新绑定本角色的骨骼。

参考编辑器用 Geometry Nodes 构造胶囊、球、连接线和锥体显示，显示体不是求解器本身。
依据：[可视化实现](https://github.com/NSACloud/RE-Chain-Editor/blob/54ed5d41a6360511b4b314c80e9b459032b32688/modules/re_chain_geoNodes.py)。
EIEM 可以实现同样的交互原则，不要求安装 RE 插件，也不将它的显示网格装进游戏 Mesh。

### 3.3 不能直接移植的部分

chain2 的数值、标志位、哈希规则和约束模型都属于 RE 的数据契约；名字相似不表示终末地具有相同含义。
不承诺 chain2 → BeyondDynamicBone 的一键等效转换，也不移植 RE 的运行时文件加载器。
若未来支持导入 chain2，必须作为显式转换工具报告不可映射项目，而不是当前主流程的中转格式。

本轮未复制上游代码；实现时如需复用，须单独检查对应文件/仓库许可。

## 4. 骨架、物理、蒙皮各自负责什么

“物理骨骼”首先仍是共享骨架里的节点；不同的是其姿态受二次运动求解影响。
骨骼的名字有 `jnt` 并不能证明它有物理。是否参与模拟取决于组件引用和选择/约束数据。
骨骼物理也不意味着每个骨骼都有 Unity Rigidbody；布料自身碰撞体与角色玩法碰撞体必须分开处理。

| 数据空间 | 作用 | 允许的绑定方式 |
|---|---|---|
| 共享骨架层级 | 定义父子关系、源局部姿态、新骨骼的挂点 | 完整骨骼路径 + 当前实例骨架根 |
| Mesh 局部表 | 顶点权重索引对应哪个 bone 和 bind pose | 第 i 项权重索引、路径、bind pose、Renderer.bones[i] 必须一致 |
| Physics 节点/约束表 | 哪些节点固定/运动、如何连接、与哪些碰撞体交互 | 显式节点引用；不能沿用 Mesh 的数字索引 |
| 原生运行时表 | team、粒子、Transform/动画缓冲、GPU palette 的实际映射 | 由该实例原生构建/注册生成，不能写入 Mod 文件 |

已有资源的局部槽位包括零权重槽仍须保留。新使用的源骨骼可追加；全新骨骼还需要创建实例节点、
生成正确的新 bind pose，并进入实际被游戏消费的动画/蒙皮映射。
基础索引关系见 [Unity bindposes 文档](https://docs.unity3d.com/6000.0/Documentation/ScriptReference/Mesh-bindposes.html)；
本项目不同部位绑定空间的实测约束以 [共享骨架记录](shared-skeleton-binding.md) 为准。

下图是**待验证的接入契约**，不是声称已查明游戏每个函数的实际顺序：

```text
原游戏动画/IK姿态 ───────────────┐
共享骨架中的新增节点与正确引用 ────┼─> 原生物理输入/构建
链参数、选择数据、碰撞体注册 ──────┘          │
                                      模拟与姿态混合
                                            │
                              原生 Transform / 动画缓冲写回
                                            │
                               每个 Mesh 的局部表与 bind pose
                                            │
                                  游戏实际 GPU 蒙皮及绘制
```

GPU 蒙皮和物理在哪个处理器上求解是两个问题；本轮看到 Burst/动画缓冲接口，尚未验证完整调度。
原则是接入游戏已使用的写回途径，而不是额外做一遍 CPU 顶点蒙皮再让游戏重复蒙皮。
必须确认 IK、动画和物理的最终写入顺序；禁止用任意 LateUpdate 写 Transform 来假装问题已解决。

## 5. 三端统一的数据契约

### 5.1 保持短路径

```text
mod.ini
meshes/coat.mesh
materials/coat.mat             （仅需要时导出）
textures/coat.png              （仅需要时导出）
skeletons/character.skeleton    （显式包含骨架或增加骨骼时）
physics/coat.physics           （显式包含物理时）
```

`.physics` 是 EIEM 的物理作者交换资源文件，不是改扩展名的 chain2，也不是 Unity 原生 `.asset`。
离线写出、Blender 读写、DLL 读取使用同一契约，不经过 FBX 或另一套运行时转换文件。
INI 只组织引用，不要求用户填写骨骼索引、team ID 或 AB 包哈希。

### 5.2 Physics 文件需要表达的数据

以下是完整源物理往返的目标数据模型。作者 v4 已把 `ClothSerializeData` 的可安全寻址数值、开关、枚举、
`gravityDirection` 与九类常用曲线作为字段路径模板写入资源；Selection、骨骼根、碰撞体引用和其他拓扑仍由作者结构单独表达。

| 记录 | 必须保存的内容 |
|---|---|
| 文件头 | EIEM schema、已验证后端标识/数据版本、坐标与单位约定 |
| 来源 | 逻辑资产来源、组件类型、组件所在相对路径和可消歧身份；原始字段的来源记录 |
| 骨架引用 | 共享骨架身份及骨骼完整路径；末端/锚点/忽略列表都可引用 |
| 物理组 | 源组件身份或新建身份、根节点、固定/运动选择、连接方式、实际参数及曲线、碰撞体引用 |
| 碰撞体 | 原生类型、绑定节点、局部位姿、已验证尺寸/方向参数；必要时两个独立锚点 |
| 约束/链接 | 真实存在的关系、作用节点、已解析参数；不把连线本身视为唯一约束定义 |
| 保留字段 | 有类型的未编辑源字段及引用信息；不把未知数据填成 0，不把内存指针当作可移植值 |

字段区分“源值”“作者修改”“未解析”，不以 UI 上一个默认值冒充源值。
未知字段可以只读保留；若其中包含尚未理解的引用或依赖拓扑，不能宣称修改拓扑后仍可安全写回。
此类操作应明确拒绝，并列出阻塞字段，不将整个字节块盲目复制到新实例内存。

同一 Physics 内的碰撞体按源身份去重，多条链引用一份定义。
跨 Physics 的共享引用必须保留指向关系；不能用相同名字猜合并，不能编辑一份显示体却悄悄生成多个不一致的运行时副本。

原物理组的修改由源身份定位；新建组有独立作者身份。**未导出的组保持游戏原状**。
删除 Blender 辅助物体不隐式删除游戏组件；禁用源物理组须显式记录该组的禁用意图。
这与 Mesh 的相机开关语义分开，不新增含糊的“丢了就删”的规则。

### 5.3 Skeleton 文件需先修好的内容

本节描述后续原生 Skeleton/Physics 装配目标。当前静态 Mesh 阶段只复用游戏已装配骨骼，明确支持范围以[共享骨架绑定](shared-skeleton-binding.md)为准。
Physics 引用闭包与整套骨架/动画重绑定仍未完成。

保留同一个资源格式和一套读写语义，但补齐：

1. 当前作者骨架的完整局部 TRS，而不是始终输出导入时缓存。
2. 源路径与作者身份的关联，能区分已有节点、新增节点和显示名修改；名称不能是唯一外键。
3. 共享层级与原 Mesh 绑定记录。新增骨骼可无原始 Mesh bind pose，但必须有明确的作者绑定姿态。
4. 不参与顶点权重却被 Physics 引用的节点；必要祖先也必须在依赖闭包内。

首版执行范围为保留源骨架、向其中增加节点，或编辑已支持的物理配置。
对已有源骨骼改父级、改绑定姿态、删除动画引用骨骼，导出器不能静默忽略：必须明确报告尚不支持该运行时操作。
后续整套骨架替换需同时解决 Avatar、动画绑定、IK 和原生缓冲注册，不能只增加一个 `Animator.Rebind()` 就宣布完成。
[Unity Rebind](https://docs.unity3d.com/6000.0/Documentation/ScriptReference/Animator.Rebind.html) 只提供相关绑定能力，不替本项目验证自定义管线。

## 6. 离线导出：先把原物理正确带出来

扩展 AnimeStudio 现有 PFB 依赖导出，而不是再写一套按角色名搜索的目录规则。

1. 从 PFB 自定义组件解析其脚本类型和真实序列化字段，并继续解析引用的配置资产。
2. 沿引用识别物理组件、配置、选择数据和碰撞体。`BoneClothItem` 等类型是适配候选，不是所有角色的唯一入口。
3. 收集 bones/rootBone、物理根/末端/忽略节点/碰撞锚点及其祖先；保留引用用途，区分蒙皮、物理、仅变换挂点。
4. 将已解析数据写入 `.physics`，相关层级写入共享 `.skeleton`。不为每个 Renderer 或 LOD 重复导出物理。
5. 在导出报告中分别记录完整、只读保留、未解析的组件及缺失引用；不能只打印“导出成功”。

仅因节点叫 LOD/shadowProxy 不把它当作骨骼导入，也不按名字一律删除；如果真实被物理引用，须作为对应类型的依赖保留。
纯挂点不必伪装成可变形骨骼；Blender 可以显示为绑定共享骨架的辅助 Transform。

如果离线 TypeTree 不足：先补该版本 schema 证据；开发者可用运行时类型/字段值比对帮助研究，
但不能把“最终每位用户都必须进游戏 dump 一次”当作主流程。
普通用户的目标仍是一次离线导出即可获得后续编辑所需逻辑信息。

## 7. Blender 交互设计

### 7.1 场景组织

```text
EIEM
└─ 每次导入的 package
   ├─ Meshes
   │  └─ LOD0 / LOD1 / ... 各 LOD 的独立 Mesh 资源
   ├─ Skeletons            一套共享 Armature
   └─ Physics
      ├─ Groups            BeyondBoneCloth 组，可含多个根和分支
      ├─ Colliders         可跨组共享的球/胶囊/平面
      └─ Visuals           不参与导出的连线与外形辅助体
```

原有物理骨骼就在 Rig 中；Bone Collection 可以分类，不能再生成每条链一套 Armature。
由配置生成的连线、约束锥和碰撞壳仅做显示，不导出成替换 Mesh。
每次 package 导入拥有独立集合身份，即使再次导入同一路径也不与旧 package 的 LOD 混合。Physics-only
导入选中已有 EIEM Rig 时进入该 Rig 所属 package；没有目标 Rig 时建立独立参考骨架和 Physics 集合。

### 7.2 用户看到什么、怎么改

- 选择碰撞体：面板优先显示绑定骨骼、类型、中心/方向和已验证的尺寸，统一左对齐；高级原生参数后置。
- 拖动位移/旋转手柄可调整局部位姿；半径/长度手柄直接修改相同的参数值，面板和显示体不能各存一套真值。
- 选择物理组：高亮对应骨骼与碰撞体，显示链根、固定/运动节点以及真实约束参数。
- 默认只显示当前组及它引用的碰撞体；另有仅组、仅碰撞体、全部、隐藏和穿透模型开关。
- 节点固定/运动颜色按解析出的选择数据产生；未知节点标为未知，不能猜成固定根或自由节点。
- 增加链：在现有 Rig 上选骨骼，创建组；从已导入原生组复制参数作为起点，显式重新绑定骨骼与碰撞体。
- 增加骨骼：仍用 Blender Edit Mode；其权重在原生顶点组编辑，物理组只负责如何驱动骨骼，不再存第二份权重。
- 改尺寸、中心和模拟参数在同一个 Physics 编辑面板完成；不要求用户翻隐藏的长键名自定义属性。
- 物理组和碰撞体 Empty 持有各自属性组。面板提供常用参数和分页后的完整原生字段，导出直接读取同一份值，
  不镜像到第二套可编辑自定义属性。

首版承诺的是准确几何/约束可视化，不承诺 Blender 内运行与游戏逐帧一致的物理。
若以后做 Blender 模拟预览，必须标注“近似预览”或证明使用了同一求解器；不能用 Blender 刚体预览冒充原生结果。

### 7.3 显隐、选择与增量导出

Mesh 的相机开关规则保持不变：只对显式选择导出的 Mesh 解释 `skip`。
Physics 辅助体的眼睛、显示器、相机开关均不生成 Mesh skip；它们不是绘制替换对象。

导出面板显式提供“包含骨架”“包含物理”及本次物理资源列表。选择的 Mesh 不自动使所有原生物理变成覆写。
新增网格依赖新增骨骼/物理但对应文件未被包含时，在导出前明确列出依赖并要求包含；不输出一份缺件的 Mod。
选中一个物理组时，其必要碰撞体和锚点依赖在导出摘要中展开；这是资源依赖，不是暗中补选别的模型。

复制物理组保留参数但分配新作者身份；复制显示辅助体不复制旧的运行时注册标识。
不同组可以共享碰撞体，删除/改动共享体时显示引用它的组，避免“只改一条裙摆却改到另一条”不知情。

## 8. Render 如何组织骨架和物理

继续使用现有资源声明与 Render 装配。下面的配置已用于 v67 无碰撞体 v1 实机：生产加载器发布通过校验的
Physics Mod，`Render.physics` 与 Mesh、材质等动作共用同一 Render 命中范围；碰撞体和 v2 原生图仍被拒绝：

```ini
[MeshCoat]
path=meshes/coat.mesh

[SkeletonCharacter]
path=skeletons/character.skeleton

[PhysicsCoat]
path=physics/coat.physics

[RenderCoat]
asset=SourceCoat
mesh=MeshCoat
skeleton=SkeletonCharacter
physics=PhysicsCoat
```

路径/名字仅为示意，不是本游戏已验证资源。用户正常操作由 Blender 自动生成这些声明。
本例使用 `asset` 命中；若增加 Render 的 `path`，其含义仍是现行规范中的相对 Transform 路径，
不能填解包资源逻辑路径。Physics 扩展不得重新定义现有路径字段。

- `mesh` 修改命中 Renderer 的 Mesh；`handling=skip` 只控制原绘制。`partner.N` 已停止支持，拆分部件由合并 Mesh 的 submesh 表达。
- `skeleton`、`physics` 是该 Render 对当前模型实例的资源依赖，不表示创建独立 Animator 或每个 Renderer 创建一套模拟。
- 只调整原物理尺寸时可仅写命中条件和 `physics`；未声明的 Mesh/材质保持原状。
- 只使用已有骨架且不改物理时，不需要增加这两个引用。
- 同一实例的多个 Render/LOD 引用同一 Physics，按资源身份取得同一个物理实例；不同模型实例各建一份。
- Blender 将同一源 Mesh 下、同一 Rig 的拆分部件输出为一个源 Render 的共享 `skeleton=`/`physics=`；
  依赖不一致时拒绝导出，不在 DLL 内猜测或创建额外 Renderer。
- 隐藏一片 Mesh 不自动关闭仍驱动其他 Mesh 的共享物理。真正关闭某物理组必须有单独的物理组状态。
- 即使最后一片引用 Mesh 暂时隐藏，也不是删除新增骨骼的指令；恢复显示复用该实例的骨架与物理状态。
  Mod 卸载或物理拓扑更新则按原生注销完成边界释放自己创建的节点，不让骨骼永久泄漏。

条件/按键/Lua 仍使用现有 Mod 变量命名空间，不引入 Physics 专属全局变量系统。
以后曝光物理开关/参数时，通过同一状态更新队列应用；UI 不直接调用原生求解器。
玩家持久化只存数值意图，绝不把 team ID、对象句柄、旧模拟缓存写进 state.ini。

### 8.1 当前 DLL 已接入的命中规划层

2026-09-07 的 v56 首次把上述语义落实到原生组件之前的规划层；该代码已随 v57 测试 DLL 保留：

- `physics=` 与 `mesh=` 一样由 `[Render...]` 的 `asset`、相对 `path` 和可选 Mesh 形状条件命中，
  并服从现有规则顺序和首个命中优先级。条件、Key 和 Lua UI 重新求值后仍走现有完整 reconcile；
  Physics 引用发生变化不会误走仅更新 shape weight 的快速路径。
- `Prefab.render.N` 只记录 PFB 与 Render 的资源关系，不限制 Render 的消费者范围。所有带 `asset` 或
  相对 `path` 选择器的 Render 都参与 Mesh 身份匹配。
- 只有在已注册模型根下遍历 Renderer 时，命中的 Physics 才会进入模型计划。单个 Renderer 的
  `sharedMesh` setter Hook 没有可靠模型根，因此只继续处理现有 Mesh 行为，不创建、删除或规划物理。
  NPC 的最终 `SetSMRRootBone` Renderer 数组同样只补齐 Mesh/材质/skip 等 Render 行为；在 NPC 模型根
  所有权尚未接入前，它不单独生成 Physics 计划。
- 计划按“Mod 身份 + 已准备 Physics 快照身份”去重。同一文件通过两个 Physics 资源名引用，或多个
  Renderer/LOD 命中同一文件时，只产生一个模型级意图，同时记录实际命中 Renderer 数量。
- `physics=` 留空或条件切换到不含 Physics 的分支，会让下一次模型计划不再包含该意图。v67 适配器会销毁
  自己创建的 EIEM host，并继续持有配置和共享 Skeleton，直到 Unity 原生组件身份死亡后才移除运行实例；
  角色 UI 的完整 Team/Process 注销已实机观察。其他 owner 和新增蒙皮节点仍需各自覆盖，不能因计划消失便
  越过该实例退休过程直接释放。

角色展示 UI 使用单独的所有权输入。`CharUIModelMono` 自己的 GameObject 是模型根，但没有可用的 PFB
逻辑路径，因此展示角色依赖顶层 Render 的 `asset=` 命中；写了相对 `path` 时仍从该 UI 模型根计算。
`OnAwake` 和 `SetVisible(true)` 注册或复用同一个模型计划，`SetVisible(false)` 仅把该 UI owner 标为不活跃并
保留计划，`OnRelease` 才移除 owner。这样后续原生适配器能把隐藏解释为暂停/禁用，把 Release 解释为退休，
并避免 UI 反复显示时重复创建物理实例。若同一模型还有其他活跃 owner，不能仅因一个 UI owner 隐藏而停掉它。

v67 已把上述计划层接到按模型实例持有的原生适配器，实机完成 AddComponent、BuildAndRun、Animator Team
注册和角色 UI owner 的原生注销。v68～v70 已确认精确作者节点、`fixed/move` Selection、新增 Skeleton 节点
驱动替换 Mesh，以及主模型、角色 UI、NPC 的同一 Mesh 身份路径。v71 又以 F10 完成 `blendWeight=1 → 0 → 1`
双向可见响应和 NPC 最终退休。当前证据仍不覆盖其余标量的完整行为语义、碰撞体或 v2 图。

## 9. 坐标、绑定姿态与参数精度

沿用 Mesh/骨架统一的游戏空间与 Blender 编辑空间转换，不能给 Physics 单独加一个猜测的 90° 旋转。
原生源图坐标在生成 Blender 预览时转换一次；新增作者骨骼的 `head_local` 已位于 Blender Rig 局部空间，
节点球、连接线和角度锥必须直接共用该空间，不能再次应用游戏空间基变换。
编辑显示放大若使用 100 倍，碰撞半径、长度、位移和新增骨骼平移都须按同一单位反算；旋转与无量纲参数不乘 100。

对列向量约定，若坐标转换矩阵为 C、对象在同一空间中的局部变换为 T，基变换按 `C * T * inverse(C)` 处理。
存在父级/Armature/对象额外变换时先换到约定空间，不直接拿 `head_local` 当作游戏父节点局部坐标。
新增骨骼的局部变换应由实际父子绑定矩阵求出，再按文件约定分解 TRS。

原骨骼 bind pose 保留；新骨骼从正确绑定空间推导，不从角色某个动作的当前姿态烘焙。
当前已有证据表明 PFB 初始 TRS 不一定等于 Mesh bind pose，不得统一重算旧矩阵。
带 shear、镜像或非均匀缩放而后端无法表达的情况明确拒绝，不静默取一个轴的比例。
胶囊两端半径、轴向及长度含义须以已验证子类契约为准，不能套用 RE 编辑器或 Blender 胶囊的约定。

参数曲线必须保留实际控制点/类型，不能全部压成一个 float；UI 范围来源于已知契约，导出不随意截断源值。
日常曲线投影只显示基础值、根端/末端倍率和线性/平滑变化；中间关键点放在折叠的数值编辑区，不显示大型曲线控件。
未编辑时继续输出原关键帧、切线和权重；用户实际修改后，才按当前关键点生成新的无权重切线记录。完整字段表只读显示，
避免形成两个互相覆盖的编辑入口。选中链节点时可查看该节点的归一化位置、采样倍率和实际参数值。
源模型顶点色、UV、形态键、原生法线/切线按 [顶点数据契约](vertex-data-contract.md) 保留；本物理设计不改变该约定。

## 10. 原生后端与生命周期

### 10.1 单一后端，不靠补丁叠加

将格式读取、实例所有权与原生调用边界分清，但不增加三套互相补漏的物理执行器：

- Physics 资源读取器：读取不可变配置/引用，做格式验证，不持有 Unity 对象。
- 实例装配器：复用现有模型实例发现与 Reconcile/Reload，解析当前实例的骨骼、碰撞体和组件。
- BeyondDynamicBone 适配：封装已验证的构建、参数更新、注册、完成、停止和释放契约；未知能力报错。

普通参数修改与拓扑重建的边界由真实 API 契约决定：可热更新字段使用原生通知；影响节点数/引用的修改进入重建。
不是先乱写字段、失败后再尝试重建的回退分支。
首次实现应替换旧裙摆专用操作的相关职责，避免新旧路径同时写同一个组件。

官方 MagicaCloth2 给出了配置后运行时构建、异步完成通知、参数变更通知等机制，是很有价值的调查参照。
其中 BuildAndRun 的返回值表示开始构建，不等于模拟已就绪。
但终末地的实际签名、完成事件与线程契约必须重新验证，不能直接导入官方 C# 示例执行。
依据：[运行时构建](https://magicasoft.jp/en/mc2_runtime_build/)、
[组件 API](https://magicasoft.jp/en/mc2_api_magicacloth/)。

### 10.2 建立一个实例的必要顺序

1. 在允许 Unity 修改的线程解析模型根、共享骨架、当前组件；先建立不被 Mod 污染的源基线。
2. 验证所有引用和字段支持性，准备新增节点与新的局部 Mesh palette/bind pose；此时不替换活跃消费者。
3. 为当前实例准备物理参数、选择/代理数据和碰撞体，重绑定到本实例；不复制源组件的进程、粒子或 team 缓存。
4. 按已确认原生契约构建并等待就绪；必须确认实际写回路径能绑定新增节点，不能只判断指针非空。
5. 在安全同步点启用新物理并发布对应 Mesh/bones 引用；确保不会出现两个 Mod 物理组竞争写同一骨骼。
6. 活跃后由游戏原生更新物理及蒙皮，EIEM 不按 Mesh 逐帧重新创建/重建物理，也不全场景扫描骨架。

这是必须满足的依赖顺序；实际需要哪些函数/完成通知仍以第 11 节调查结果实现。
原生 BuildAndRun 若自动开始写入且没有可控暂停/就绪边界，必须先解决这一边界，不能假装步骤 4 与 5 已隔离。

2026-09-07 本机指令复查：初始化受全局模式影响，可能在 Awake 或 Start 中发生，Start 还会触发 AutoBuild。
新组件工厂必须解决“配置前禁止自动构建”，不能在 AddComponent 返回后才假定初始化尚未发生。
BuildAndRun 的通知可同步早于返回；异步取消分支还可能完全不通知，详见

原组件参数修改必须作用于该实例拥有的数据；若配置被多个实例共享，先建立实例配置副本。
新建组件只复制已理解的序列化参数，并重绑引用；**不得 memcpy 一个运行中的组件或连带克隆人物整棵 GameObject**。

### 10.3 资源共享与实例隔离

物理实例所有权键为“Mod 身份 + Physics 资源身份 + 当前模型实例代际”；骨架扩展同理。
同一个角色被世界、角色展示 UI 或另一个实例使用时，分别拥有模拟状态。
同一实例的多个 Renderer 只是消费者，不分别重置或销毁共用物理。
原生物理实例必须持有共享 Skeleton 的使用权；只计 Renderer 引用的回收器尚不足以安全回收物理骨骼。
该使用权要等原生构建/模拟/动画写回均不再引用新增节点后才释放，不能用 Mesh 可见性代替。

多个 Mod 使用同名新骨骼，由内部 Mod/作者身份消歧，Blender 显示名无需变成长哈希。
不同物理覆盖同时要求拥有同一源组件，或新增物理组意外同时写同一批输出骨骼时，明确报告冲突；
不能靠执行顺序碰运气。原生已定义的动画/物理混合不属于这一冲突，必须保留其混合契约。

### 10.4 F10、换图和卸载

资源定义与运行时对象分开；当前 Mod program 的代际是“还能否执行”的依据。
旧异步回调完成时须重新检查 program 代际与实例有效性，失效结果仅清理，绝不重新挂回旧 Mod。

卸载/重建必须满足以下顺序约束：

1. 撤销旧组继续写入/继续构建的权限，使用原生停止及任务完成机制同步；不使用固定 Sleep 猜任务完成。
2. 解除它的碰撞注册和动画写回注册；确认相关任务不再访问待释放对象。
3. 在安全点恢复/重绑定消费者到其源 Mesh、源 bones、源物理配置及游戏控制关系。
4. 没有消费者和原生任务引用后，才释放 Mod 物理状态及新增骨骼；源骨骼/源组件不归 Mod 销毁。

具体 API 调用顺序必须服从游戏原生注册/退出契约；不能把上述逻辑约束当作猜偏移清零的实现指南。
已查实 Dispose 在构建期间会延迟清理，返回不代表 Task 退出；isDestoryInternal 标记置位后也仍有管理器调用。
OnBuildComplete 不是取消退出的必发通知。正式状态机不能仅凭这些任一值销毁共享骨架，
也不能让已取消代际的完成事件重新激活 Mod。
若恢复失败，保留恢复所需引用并报告，不丢账本、不把当前 Mod 状态重新记成源状态。
准备阶段失败不发布半套资源；已经活跃的实例需要按拥有关系撤销，而不是轮番尝试其他求解器。

地图/模型卸载后清除该实例的模拟、映射和注册信息；不要把 PFB 缓存对象当作已恢复的场景实例。
池化对象重新启用时按实际游戏 reset/rebind 生命周期处理，不能把上次地图的 team/缓冲句柄视为仍有效。
LOD、屏外剔除、传送/换图恢复遵循原生重置与时间步策略，不能关闭渲染后留下无限累积的模拟时间。
官方碰撞配置也强调注册与正确缩放的重要性，但终末地的具体约定仍需验证。
[参考：碰撞设置](https://magicasoft.jp/en/mc2_collision_setup/)。

## 11. 接入前置条件

先取得真实原生组件的构建、取消与销毁记录，并确认 Task/Job/动画写回的退出边界；
再用不依赖 Blender 的 DLL 最小新增链实验验证 Animator 接纳、模拟位姿、网格驱动和安全注销。
v67～v71 已按这一顺序完成 v1 无碰撞体范围，并接通对应 `Render.physics` 与作者端组合导出；原生 v2 与碰撞体
普通函数返回、跟踪计数归零和日志无丢失，单独或组合都不是任务退出凭证。
这些前置条件限制依赖原生构建、绑定与对象释放结论的操作；不阻塞离线格式、Blender 编辑工具、
资源读取、编译、静态分析和宿主测试。缺少证据时记录具体的“尚未验证”项，不将整个项目停工。

## 12. 验收矩阵

| 测试 | 必须观察的结果 |
|---|---|
| 原物理原样往返 | 类型、曲线、节点角色、引用和已知数值保持；未知字段未被清零；本轮不以近似模拟一致冒充原生一致 |
| 改碰撞半径/位置/方向 | Blender 显示尺寸、导出数值、游戏实际碰撞范围一致；恢复后回到未污染源值 |
| 保留源骨架，Mesh 用表外源骨骼 | 路径/权重/新 bind pose 正确，零权重旧槽不丢；不重算旧槽 |
| 真正新增一条骨链 | 新节点挂到当前实例正确祖先；注册、模拟输出、GPU 蒙皮均可追踪，原节点动画未被抢写 |
| 多 Mesh / 多 LOD 共用一链 | 同实例只构建一次，LOD 切换不产生重复模拟或清空共享状态 |
| 所有引用 Mesh 暂时隐藏后再显示 | 物理所有权仍在时保留新增骨骼，不因渲染消费者为零而提前删节点；卸载后仍能安全回收 |
| 两个同角色实例 | 姿态、碰撞与缓冲句柄独立，销毁一个不影响另一个 |
| 改尺寸/曲线后 F10 | 支持热更新的正确通知，需重建的正确重建，不混用旧拓扑缓存 |
| 注释→F10→换图 | Mod 物理、骨架扩展及附属资源均不复活；游戏源状态正常 |
| 启用→F10→禁用→F10→再启用 | 不消失、不扭曲、不重复注册，不将 Mod 写成源基线 |
| 构建期间 F10/换图/退出展示 UI | 旧代际完成回调不能发布；原生任务无悬空引用，内存不会持续增长 |
| 重名/缺骨/缺引用/未知类型 | 指出资源、组、字段/骨骼路径并停止相关操作，不猜近似名字、0 索引或单位矩阵 |
| 保存旧 .blend、更新插件、重导出 | 作者数据仍可解析，当前 DLL 格式由导出器生成，不把旧 INI 文本当工程真值 |
| 隐藏编辑辅助体 | 不产生 Mesh skip、不禁用游戏物理、不自动导出显示网格 |

离线测试使用合成骨链和固定源样本校验数据；运行时适配器测试校验顺序、引用、代际和失败释放；
游戏验收独立记录画面与映射证据。三者不能互相替代，编译通过不等于物理可用。

1. BeyondBoneCloth 完整的序列化字段、参数单位、碰撞体具体子类，哪些参数可热改、哪些必须重建。
2. 当前文件已确认保留运行时代理/约束构建代码、取消检查及释放路径（见原生物理接入调查）；
