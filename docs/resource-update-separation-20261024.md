# 资源更新与命中、结构计划分离

2026-10-24。实现与离线验证记录。Mesh、Material、Texture、Physics、Effects 和混合修改统一迁移；没有部署到游戏、改写用户 Mod 或保存 Blender 工程。游戏内画面、F10 总耗时及帧率仍需实机验收。

## 职责划分

| 层 | 保存什么 | 何时变化 |
| --- | --- | --- |
| 命中与结构模板 | 精确来源、Prefab/Renderer、骨架槽、对象布局、PPtr/名称重定位、依赖和证明 | 来源或真实结构变化 |
| 原生资源 | 作者网格、材质、贴图、物理、特效字节，以及离线生成的帧和包围盒 | 对应内容变化 |
| 包快照 | 模板引用、资源版本、控制声明和提交索引 | 发布新版本 |

作者编译器从真实序列化字段保存字节来源。相同 float 字节不会被猜成同一个参数；引用重定位、生成名称和被改写的字段清除旧来源。Mesh 帧按资源生成，Renderer 包围盒按 Mesh/骨架槽/变换上下文生成，不随每个 Prefab 重复构建。

`eiem_addressed_resource_update.h` 统一判断五类及混合修改能否复用。`eiem_resource_snapshot_publish.h` 只读取作者清单、来源选择、字段绑定和发生变化的生成缓冲，不读取全部来源模板或证明，不逐 Prefab 重建。任一变化未被已验证字段范围覆盖，整体回退冷编译，不能只发布混合修改的一部分。

DLL 保持原生读取视图、统一快照和实例生命周期。没有接入作者构建器，没有在帧循环扫描规则、展开 Mesh 帧、计算包围盒或重建物理组件。多 Mod 真正写入同一原生输入时，仍需在后台合并已编译对象与引用。

## 存储和兼容

新容器 `EFF_MOD_BLOCKS/2` 使用小 `compiled.bin` 索引和 `compiled.blocks/<SHA256>.bin` 不可变内容块，沿用原有 INI、来源目录及作者资源。分发和备份必须复制完整 Mod 目录，不能只复制新的 `compiled.bin`。

未变块在同卷暂存时建立硬链接，跨卷按块复制；变化块只写一次，最后替换小索引。Blender 不再复制旧巨型编译包、重新压缩全部证明及完整哈希整包。成功校验发布后清理退休侧车；异常保留回滚文件。

新 DLL 仍读取旧单文件 packet 和 `/1`，并可与 `/2` 混用。旧 Mod 不因本次升级或游戏整体指纹变化直接失效。新 `/2` 包需要配套 DLL；Blender 在导出前检查编译器与安装协议声明。

旧代际证明可能延迟访问。读取器固定旧快照，保证作者清理旧块、移动或删除 Mod 目录后，仍在使用的旧证明可读；随消费者退出回收。硬链接不可用时保留共享删除文件句柄，避免复制巨型旧包。

索引与不可变块有原子提交/完整性保护；整个作者目录仍是逐文件替换及异常回滚。强杀进程或断电发生在多个作者文件替换之间时，尚不能保证整目录严格旧版或新版二选一。

## 共享结构与身份

- 包级 TypeTree 字典按完整结构去重，证明引用字典 ID。before 布局完整保存，after 按原对象序号及偏移/尺寸/类型差分编码；新增对象保留完整身份。
- 原生视图按单个 TypeTree payload 共享静态元数据，保留各 Prefab 类型顺序、脚本槽、依赖与专有字节。字典和公共清单均压缩，旧 raw 公共清单继续可读。
- Mesh 控制标记由 Mod owner、Part 和精确 target 决定，不随顶点内容摘要变化。真实 Chen 顶点差分曾定位到 `m_Name` 因内容变化不等价，已修复。旧标记继续可用，旧包新增 Prefab 的准备描述沿用原计划标记。
- 模板摘要和绑定后资源版本分开保存。反复 Save/Load 的有效身份、包摘要和 generation 不漂移。
- 快更完整性来自模板块、原来源、作者资源及生成缓冲摘要，不再错误核对变化前的整体冷编摘要；结构、范围、前像、名称和引用检查保留。多 Mod 合并后的实际输出仍计算精确摘要。

## 复用与回退

| 修改 | 当前处理 |
| --- | --- |
| 相同布局顶点、现有材质数值、同尺寸/格式贴图、已绑定物理参数 | 更新资源及必要派生缓冲，来源/证明复用 |
| 特效载荷或挂载参数 | 更新相应资源，角色结构可保持 |
| 多种资源同时修改 | 同一次校验、同一快照提交 |
| 数据长度、贴图声明、骨骼/引用结构或未绑定字节改变 | 安全回退冷编译 |
| 新 Prefab 消费者 | 按实际新增来源编译，保留旧 schema ID 前缀 |
| 完整当前索引移除来源/资产/候选/依赖 | 按完整索引退休，不能 union 回旧发现 |
| 只有部分来源选择 | 校验后继承旧发现，不能推断旧来源已经删除 |

旧内部原型的内容相关标记禁止直接套用新快路；绑定结构升级后触发冷迁移，不影响旧已发布包读取。

## 回归与实机边界

覆盖旧 packet、`/1`、`/2` 混用、多 Mod 合并/删除恢复、写入中断/缺块、并发 generation 拒绝、旧快照固定、目录迁移、shared schema/delta 和重复 Save/Load。166 输入 gly 动态来源回归中，新增一个来源只编码一个来源/证明，追加时旧证明读取为 0；新增输入逐字节等于冷编，reload/retire/replace/旧快照仍可读。旧 packet 与 `/1` 的 Prepare/Encode/Decode/Compile 也保留原标记且实际输出一致。
