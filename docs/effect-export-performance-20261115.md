# 特效冷导出与游戏逻辑引用

Blender 资源选择和导出不读取全局 `.eidx`，不从安装目录反向寻找来源 Prefab。导出只处理当前特效逻辑、作者自己修改的资源、可编辑底稿，以及游戏资源的逻辑声明。

## 资源声明与运行时

- 已导入游戏资源：从已有作者目录保留所选原生身份和游戏来源租约，不复制其游戏纹理、材质或 Shader 到运行时载荷。历史直接 PPtr 继续兼容。
- 未在本地导入的游戏资源：填写 `assets/...` 或 `packages/...` 逻辑路径。编译器生成私有原生引用占位，记录 CAB 字符串与 PathID 的精确字节位置；INI 为装配中心。
- 可选来源 Prefab：填写 `assets/.../*.prefab` 即可，不要求 Blender 对象、本地 `.efffx` 目录或根对象名称。根名只作为已有来源的额外核验信息。
- 需求发生时：DLL 通过现有游戏 ResourceManager 请求资源或来源 Prefab，保留其加载句柄；复用当前游戏清单/VFS 的定点查找，把占位原生地址绑定到当前资源。原始输入不修改，也不整包复制。
- 直接路径没有公开清单入口时，只在显式声明的来源 Prefab 依赖闭包内选择唯一的类型/资产名，不全局搜索消费者，不实例化来源，不播放来源特效。不存在或歧义的资源拒绝加载。

来源逻辑声明由 Blender 的“按逻辑路径绑定资源”弹窗生成，无须用户手写 INI。缺少本地像素可能无法离线预览，不影响保存声明与编译。

运行时新增逻辑引用仍需实机视觉验收；离线编译成功不能证明路径在当前游戏清单中公开可加载。已导入资源的历史直接 PPtr 尚未全部改为运行时重定位，因此本次不保证所有旧包跨游戏更新自动适配。

## 性能依据

初次性能剖析：多用例执行中的 8 次 `resolver_inputs()` 累计约 34.9 秒；单次首次导出约 23.2 秒。该函数及其编辑端调用已删除，独立索引诊断 CLI 不参与作者导出。

移除索引后，真实用户工程 `G:\zmd\机械刀\幻枢归奇.刀_轴向方框自旋_20261114_before_particle_repair.blend` 的柔光根（三个有效发射器）冷导出仍约 6.28 秒。继续剖析发现：作者底稿打入了约 18.88 MB 未修改游戏 Shader 原生文件；同一次导出的最终一致性检查还重复执行贴图 BCn 编码。

修复后，同一原始工程、全新 Blender 进程和全新临时原生构建目录，源码版实测约 **3.02 秒**。安装版覆盖导出 `mods/lizi` 实测 **3.30 秒**（无 profiler；旧构建复用 0 / 新构建 1）：作者整理 1.74 秒、原生构建 1.22 秒、输入校验 0.11 秒、发布 0.24 秒。可编辑作者文件由 **15,352,617 bytes 降为 1,535,477 bytes**；运行时两份特效载荷仍共约 0.58 MB。最终安装版的覆盖导出数据以 `real-export-result.json` 为准，不能拿导回工程或缓存命中时间代替原工程冷导出。

具体规则：

- `eiem_effect_source.author_projection` 只精简终端游戏 Shader 文件。必须有游戏逻辑来源，文件内只能包含 Shader 与 Unity Bundle 辅助对象；显式 `runtimeEmbeddedBundles`、混合其他资源的文件及缺少游戏逻辑来源的 Shader 保留完整原生字节。
- 底稿里的 Shader 保留原生身份、逻辑路径和真实 Shader 名称，标记 `game-reference`，由游戏原 Prefab 资源租约提供程序；不保存其 GPU 程序副本。可编辑粒子、材质、贴图和 Mesh 模板保持原生内容。
- 投影只发生在输出底稿中，同时更新底稿 manifest、catalog、generated-files 回执以及 workspace/edit 来源摘要；不改原 `.efffx` 或用户 `.blend`。导回后的底稿可以独立校验、修改并原生重建。
- Shader 名称读取按真实 TypeTree 跳过无关字段，不构造、重编码整份 GPU 程序。来源字节和 schema 仍有摘要校验。
- 单次导出使用一个 `ExportSnapshot`，相同像素只执行一次 BCn 编码；发布前仍读取实际像素与全部参数。导出期间改变像素或采样设置会改变作者载荷并拒绝发布。该对象不跨导出保留，不用缓存命中掩盖冷构建成本。
- 作者归档仍做路径、CRC、摘要和来源验证；完整保留作者自有资源，不以跳过验证换取速度。

真实安装版导回验证：三发射器作者文件导回 → 全新目录原生重建约 1.87 秒；只选择一个发射器、修改速度后再冷构建约 1.62 秒。另验证同一事务只编码一次相同像素、改变像素重新编码且载荷变化。这些输入与原工程不同，时间单独记录在 `installed-roundtrip/result.json`。

本机已安装 Blender **0.50.19**，回执 `bin/local-deployments/20261115-102500-054/Blender.json`。237 项作者/更新回归通过（1 项跳过），安装文件摘要与源码对应，Manager 附带的原生校验器接受实际 `mods/lizi` 包。实际包核对三个发射器、目标武器逻辑路径、LOD0～3 和作者 Empty 层级；未保存用户工程、未推送或发布 Release。本次仅修改 Blender 导出与底稿，无新的游戏内视觉验收结论。

证据目录：`diagnostics/effect-export-performance-20261115/`。最终本机部署后的测量以 `real-export-result.json` 为准，`real-project.prof` 为单独带剖析开销的运行，不能作为最终耗时。

## 回归入口

- Python 冷构建不启动索引解析进程；绑定变化使构建失效；来源路径无需本地 donor；跨根复制保留所选资源证明。
- AnimeStudio `--logical-reference-relocation` 使用真实源特效和未导入的纹理路径构建，验证原生 PPtr 与三处字节地址完全一致。
- `effect_debug_smoke --relocation-check` 检查不可变输入、跨范围读取、负 PathID、按 Bundle 延迟绑定，以及错误地址/源字节/重叠拒绝。
- `effect_game_dependencies/smoke --relocations <Mod>` 通过真实 INI、生产 Catalog 和资源文件打开路径验证覆盖、声明范围与代际失效。
- 真实工程通过生产 `ExportBatch` 冷构建，发布后保留三个发射器、武器逻辑目标、全部 LOD 和 Empty 挂点。
