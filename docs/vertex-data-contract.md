# 顶点数据契约

更新：2026-10-04。本文规定作者顶点数据与原生写回的契约，历史实验另行归档。

**当前实现（Blender 0.11.1）：原生切线能用就用；新增/外部几何没有可用切线时，导出时生成。**
同一个网格中也按数据区分：保留有效源值，仅为缺失部分生成。旧解码调查、当时的待办和回归数量
已删除的历史试验不描述当前导出器状态。本文不配置 IDE/宿主的审查或提示行为。

当前解包源码 [AnimeStudio/Classes/Mesh.cs](https://github.com/ssice-a/AnimeStudio/blob/master/AnimeStudio/Classes/Mesh.cs) 的压缩 NORMAL 分支调用
`DecompressEndfieldFrame`，同时填充 `m_Normals` 和 `m_Tangents`；Blender 导入将切线向量和符号
保存到对应 Mesh 属性。当前不使用“只解码法线，再统一重算源切线”的流程。

## 必须采用的规则

1. **原生解码与重新生成不是同一件事。** 原网格的法线、切线、手性符号、UV 和其余通道应先解码并保留。
   从 UV0 和最终法线重算不能保证恢复原切线；算法、接缝、三角划分与原作者数据均可能不同。
   删除部分面不触发统一重算法线/切线/描边 UV2。缺少可用切线时，由当前法线和 UV0 生成所需切线。
   保留与生成是两种来源；导出日志区分保留顶点数与生成面角数，生成数据不作为原生解码证据。
2. **按实际 Shader 接口解释数据。** 存储格式由原始通道描述和已验证的标志决定；
   用途由实际 Shader/Pass、关键字和生效参数共同决定，不能按角色名或单个保存字段猜测。
   每个子网格的材质槽都要考虑，不能只看槽 0。进入绘制之前的原生形变/蒙皮处理也必须支持该布局；
   TypeTree 回读成功和 Shader 能解码源缓冲区，均不能替代这条处理路径的验证。
3. **UV 编号必须明确。** 本项目 UV0/UV1/UV2 为零起始，UV2 是第三通道。
   Unity 的 `Mesh.uv2` API 指第二通道，不能混用。GPU TEXCOORD 语义也不必然是贴图 UV。
   UV 通道允许空缺：只有 UV0/UV2 是合法输入，不能以“必须连续”为由补造 UV1。
4. **Blender 使用真实编辑数据。** 法线通过 `normals_split_custom_set` 参与平滑着色；
   未修改时允许源备份保留原浮点值，修改后不能用备份压过编辑。
   UV、顶点色、形态键进入各自的原生系统。切线及 UV 的 Z/W 用 Mesh Attributes 保存。
5. **往返测试必须说明起点。** 已有包 → Blender → 输出相等，只证明输入包中已有数据得到保留，
   不证明原始 AB 的所有通道都已导出。修复解包必须另测原始 AB → 解析器 → 写包器。
   离线通过不等于运行时 GPU 输出/游戏画面验收。

## 作者数据与原生写回（2026-10-04）

解包、编辑和游戏输入各有契约，不能把作者文件当成可直接加载的 SerializedFile。

| 层次 | 保留或生成的内容 | 兼容边界 |
|---|---|---|
| 原生来源 | 原始对象/schema/流字节、通道描述及特殊标志、资源身份和 Renderer 使用上下文 | 未修改字段与未知对象保持；源布局只证明原 Mesh 的既有功能组合可用 |
| 作者数据 | 可编辑的位置、法线、切线及手性、UV、索引、逐 Mesh 骨骼槽/权重/bindpose、形变 | 继续使用现有 EFFMESH v6 与 `.blend`；编辑语义不绑定一个固定 GPU stride |
| 发布与原生重建 | `mod.ini` 和独立资源增量，结合当前源模板生成最终原生字节 | 在反序列化前按实际 Mesh 功能选择已验证布局；描述符、数据、步长、流偏移和对齐一起更新 |

当前已验证的 Endfield 原生帧存储规则如下，仅覆盖写入器现有的源布局契约：

| Mesh 功能 | stream0 原生存储 | 当前输出规则 |
|---|---|---|
| 无形变通道 | Float32 position3 + 32 位 packed normal/tangent frame；stride16 | 保留已支持的 packed-frame 布局 |
| 有非空形变通道 | Float32 position3 + normal3 + tangent4；stride40 | 将已支持的 packed frame 解码并展开；已展开输入保持幂等 |

这里的 packed frame 由通道高位标志与数据位模式共同定义，不能因为描述符 `format=0`
就把它当作普通 Float32 法线分量；它也不等同于 `m_MeshCompression`。原始身体 Mesh 的
`m_MeshCompression=0`、normal `dimension=0x31`，仍使用这种帧编码。

这次原始身体没有形变通道，作者身体新增两个；沿用原始 packed-frame 存储进入了不同的原生
形变/CPU 蒙皮路线。仅展开帧存储、保留位置/索引/权重/骨骼槽/形变及其余对象后，故障帧的
148 个非有限位置分量在正常帧降为 0。该对照确认本例的存储与处理路径不兼容，尚未直接观察
原生内部具体错误读写指令，也不证明所有 CPU 蒙皮 Mesh 都必须使用同一种布局。

重建必须满足以下约束：

- 源描述符与原始字节用于保真和解码；新增功能不能无条件继承原来的存储方式。
- 转换布局时保留几何与属性语义，不能只改描述符或只增大步长。其他顶点流的有效数据保持，
  重新计算流起点与长度；Bounds 从实际位置步长读取。
- 每个 Mesh 独立维护索引宽度/范围、骨骼 palette、权重和 bindpose，Renderer 的 bones 顺序与之对应。
  拆分顶点时索引、面角属性、权重与形变索引必须使用同一映射；不同 Mesh 不共用一个数字索引表。
- 当前 C++/Python 写入入口仍要求已验证的源 normal `dimension=0x31`，不宣称支持任意原生顶点布局。
  新 schema、编码或功能组合应明确报不支持，补齐解码、写回和实际处理/GPU 验证后再开放。
- 格式验证分为字段/类型与字节范围校验、独立解码与对象图核对、原生加载及实际 GPU 输出。
  新增形变等会改变处理路径的功能必须覆盖最后一层，离线往返相等不足以放行。

该规则由原生写入器自动执行，不增加 INI 布局选项，不升级顶层发布格式，也不要求重做已有
作者工程。已有 packed 作者资源按其解码值展开；当前 Python 构建仍先打包再展开，不能宣称
它逐位保留新编辑的浮点法线/切线。后续直接生成浮点布局可避免这次额外量化，需要另行回归。

实现入口：`src/eiem_mesh_frame_storage.h`、`src/eiem_mesh_input_builder.h` 与
`tools/nativepack/mesh.py` / `delta_apply.py`。真实源 Mesh 回归见
`tools/diagnostics/shaped_frame_writer_regression.cpp`；抓帧对照与正式部署的验证边界见
[当前热重载验收](hot-reload-testing.md)；离线/源码检查入口见[代码架构](code-architecture.md)。

## 缺失切线导出生成（2026-09-07，0.11.1）

- 缺口复现：真实后台 Blender 中，一个有 UV0/法线但没有切线属性的新网格，经旧 `write_mesh`
  输出空切线数组。此前已有源数据复制分支，没有对应的生成分支；这是本次修复点，不是原生解码回归。
- `mesh_export_tangents` 按顶点检查源向量/符号。有限、非零向量和 ±1 符号视为可保留帧；
  不额外归一化或正交化源数据，保留 float32 和负零。此检查不能判断作者复制的旧方向是否仍符合新 UV。
- 无属性或合并后零填充/无效帧：在临时 Mesh 副本上调用 Blender
  [`calc_tangents(uvmap="UV0")`](https://docs.blender.org/api/4.2/bpy.types.Mesh.html#bpy.types.Mesh.calc_tangents)，
  使用当前自定义法线，只取缺失处的生成结果。作者属性和源切线不被写回或覆盖。
- 新生成的符号从 Blender 坐标转换到源坐标；已保存的源符号则原样保留。
  生成切线和符号作为面角流参与拆分，避免同 UV/法线但镜像手性不同的面角被错误合并。
  位置、权重、骨骼槽、UV、颜色及标准形态键增量继续使用同一个源顶点映射。
- 没有 UV0 且没有源切线时维持无切线输出，不补造 UV；有部分源帧但缺失帧无法通过 UV0 生成时报错。
  仅有切线向量或符号、属性类型错误仍报错，不通过静默清空源属性处理。
  孤立顶点无面角导数：有效源值保留，否则使用不参与绘制的零占位。
- Blender 切线接口支持三角面/四边面；需生成切线的 N-gon 先三角化。
  若用户主动重做全部切线，可删除成对的切线属性再导出；这表示生成，不表示恢复源数据。
  普通切线生成不代替游戏专用描边 UV2 或形态键切线增量生成。
- EFFMESH v3 不变，DLL 继续消费切线数组，不增加运行时回退或新 INI 选项。

回归入口：设置 `EFF_BLENDER` 后运行 `python -m unittest discover -s tests -p test_blender_tangent_export.py -v`。
测试先复现空数组再验证生成，覆盖源切线逐位保留、混合新旧顶点、镜像切线接缝与源坐标副切线方向、
自定义法线、稀疏 UV0/UV2、孤立顶点、重复导出、导出不改工程及生成数据再次导入后的往返。
测试在独立后台 Blender 5.0.1 中运行；本轮不修改用户场景、游戏 Mod 或部署 DLL，不作为游戏着色验收。
本轮 `test_blender_*.py` 的 10 个测试全部通过（已提供 MSVC，包含实际 C++ 解析检查，无跳过）；
源切线接缝往返、共享骨架、形态键、选择导出和插件开发重载回归一并通过。
