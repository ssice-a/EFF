# Blender 重复全部资源导出优化

2026-10-17。本轮只更新 Blender 作者导出和其配套离线编译器，保持 Mod 格式、完整消费者覆盖及游戏 DLL。已经本地安装，没有发布 Release 或写入游戏 Mod。

## 定位与改动

用户使用“全部资源”导出。固定 si 副本中，作者不变时已有完整产物复用；只修改一个 Float32 顶点后仍走完整 `Compile`。几何变更还没有独立的逐 Mesh 增量编译分支。早期诊断直接调用底层导出、绕过正式 facade 的依赖图更新抑制，不能据此认定正式按钮总是让全部快照失效；正式入口对照确认只改一个网格时其他九份快照可以复用。

本次实现：

- 本地 Mesh 快照不再因普通对象变换或骨架姿态变化失效；仍核对 Mesh 修改、权重、形态、槽位及完整静态骨架绑定。骨骼数组属性按实际内容摘要，防止原地修改数组但 `repr` 不变导致误命中。
- 每个对象只保留最新快照，防止一个反复雕刻的对象用历史版本挤走未改对象。
- 形态坐标和面材质索引用批量 RNA 读取生成摘要，保持对实际编辑的检查。
- 原生材质字段按来源内容证明、全部非纹理绑定参数与编码器复用；每次仍验证当前来源文件，贴图引用独立处理。
- 磁盘图片按捕获的实际文件 SHA256 复用 RGBA 解码。每次仍读文件字节，不只依赖时间/大小；脏图、打包图和生成图不使用此跨导出复用。RGBA 缓存总预算 128 MiB、最多 128 项，大图仍可导出；打开工程清理会话缓存。
- 离线字节配方使用长段块比较和只排除不可能命中的前缀位图。正候选仍使用原 32 字节 hash、相同首个 anchor、逐字节精确前缀及相同 span 合并规则；没有改文件格式、匹配覆盖或验收步骤。

## 对照与边界

`bin/export-optimize-20261017/background-bitmap-report.json` 使用单独的 Blender 后台进程加载同一已保存工程，正式 `addon.export_package` 入口，十个网格、ALL、LOD0、包含控制。只在该后台进程修改 cloth_01.001 的一个顶点，恢复后退出，不保存源工程。

| 情况 | 修改前 | 修改后 |
| --- | ---: | ---: |
| 已预热，修改一个顶点后全部导出 | 11.319 s | 10.234 s |
| 紧接着完全不变再导出 | 5.760 s | 5.076 s |

单顶点修改时九份快照命中、被改的一份重建；完全不变时十份全部命中。这两种情况下，新旧导出的全部文件逐文件 SHA256 一致，包括作者资源、控制、来源描述与 compiled.bin。首轮预热存在源模板/作者元数据初始化，不用于严格的冷性能结论。机器负载和 Windows 文件缓存未控制，不能承诺所有工程固定改善此比例。

固定独立作者快照的四次新旧编译器交错对照，compiled.bin 13,855,569 字节逐字节一致，SHA256 `42c872202b03e0b3b8661bc77a3050ffa00e12f5f7c023f0eda0d1b5ee2dc448`。前缀筛选降低匹配阶段 worker 累计时间，但完整冷编译墙钟没有稳定改善；不能把 worker 时间相加或将此项描述为整体数倍提速。没有证明峰值内存降低。

安装后当前实时工程的独立输出复测：首次 13.008 s、下一次 7.595 s；第二次十份 Mesh 快照全部命中，材质字段重建为零，来源索引和完整编译结果复用。此时实时工程与已保存快照不同，不能用它替换上述固定输入的新旧对照。实机选择、模式和项目路径保持，未保存工程、未发布 Mod。测量见 `live-check.json`。

32 项纯导出测试、25 项离线提交测试（1 项按原条件跳过）、后台 Blender 快照回归、三轮注册/注销/重载及 C++ 完整集合回归通过。覆盖骨架姿态与静态绑定、原地数组修改、形态编辑、面槽位修改、连续雕刻与未改邻居、打开工程/丢失 tracker、源文件损坏以及同时间/大小但贴图字节已变。真实完整导出用于锁定产物等价。

## 本地安装

配套编译器：`tools/Blender/nativepack/eff_resource_pack.exe`，SHA256 `712BC9C5FCDC8A80FCBD2A1A8E22BE00E33A276D7A5488888138B056624215C6`。新旧协议声明完全一致。旧文件、安装清单与测试保留在 `bin/export-optimize-20261017/`。

安装目录是指向源码插件目录的 Junction；当前 Blender 会话只更新相关函数，保留已注册类与 handler 身份，下一次导出即可使用。游戏 `plugin/eff.dll` 未更新，SHA256 仍为 `A20D00FBD732C925749A764F8374B71DC5A1B1019E61392A69169AACB743A8BC`。

继续大幅提速需要独立实现几何变更的受影响输入重编译。雕刻可能影响法线/切线、Mesh 与 Renderer bounds、形态及骨骼绑定，不能直接跳过全部 PFB 或只替换顶点字节。本轮没有冒充完成这条增量路径。

## 导出被来源锁拒绝的后续检查

用户随后报告无法导出，已从当前 Blender 的 Info 报告读到“解包来源正在更新，请在 AnimeStudio 完成后重新导出”。该报错来自来源目录的独占命名 mutex；其他 Blender 导出和后台性能对照也会持有它，旧提示没有记录占用者，不能唯一归因于 AnimeStudio 或某个进程。当前两处来源从独立进程均可立即加锁，未发现锁仍占用或泄漏。

已把 canonical `tools/nativepack/author_source.py` 和安装副本的提示改为“解包来源正被其他导出或 AnimeStudio 更新占用”，附具体目录，保持原有更新保护。当前会话同步加载。临时目录完整复测成功（21.184 s，此轮作者内容/机器负载与上述性能快照不同），随后从独立进程再次确认两处锁都释放。生产 Mod、工程文件和选择未写；证据为 `bin/export-failure-20261017/retry.json`。后台对照结束后用户可正常重试，不应绕过来源更新保护。
