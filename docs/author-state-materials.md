# 作者控制、持久化与独立材质导入

本文规定作者默认值、玩家持久化和材质导入的现行行为。当前版本及验证状态见[文档索引](README.md)。

## 变量

```ini
[Constants]
persist $size=0.25
$ui_open=0

[RenderCloth]
asset=SourceCloth
shape.Inflate=$size
```

`persist` 只标记变量的保存策略，不是另一种表达式。普通变量重载后用作者默认值；
持久化变量在换图、F10、重启后保留玩家调整值。状态文件固定为该 mod.ini 旁的 `state.ini`，
只保存数值，不保存 Render、Unity 对象、指针或动作。已移除/注释的变量不会因状态文件而重新生效。
不同 Mod 目录隔离；旧状态只应用到当前仍声明为 persist 的变量，按现有数值约束重新验证。
文件损坏、写入失败明确报告；临时文件写完再原子替换，不回写 mod.ini。
使用现有按键工作线程合并写入（最多每 250ms 一批，不轮询磁盘）；F10 和正常退出强制提交。
强制终止进程可能损失最后尚未提交的一小批调整，不承诺崩溃瞬间保存。

Lua `mod.default("$name")` 读取作者默认值；模板的“恢复默认值”按钮通过普通 mod.set 事务重设
导出的形态键/切换变量，不重置 UI 打开状态。无 UI 的 Mod 可退出游戏后删除对应 state.ini，下次启动恢复默认值。

## Blender

- 新增（不在源形态键元数据中）的非 Basis 通道自动生成控制变量，默认值取 Blender 权重。
  原生通道默认仍由游戏驱动，只有显式添加控制才接管。UI 模板保持可选。
- 自动控制可禁用；显式控制可设置默认值。控制声明、自动身份和开关状态随 .blend 保存。
- 变量身份不依赖导出顺序，网格数据/控制/切换组自动保存标识；共享数据共用变量，独立副本分开。
  显隐切换使用稳定状态编号，新增或重新排列状态不把旧编号解释成另一个状态。
- 不更改已有形态键几何、法线、切线或蒙皮处理。原生多帧通道的手动滑条限制维持不变。

## 材质

材质属性页增加“导入 EFF 材质”按钮：选离线导出的 `.mat`，新建完整材质数据块并分配到当前槽，
不原地覆盖旧数据块，避免改变其他共用者。载入 source、真实参数、贴图引用和基线。
需要 Texture 声明时，从此文件所属资源包的 mod.ini 解析；没有本地声明但只需继承的游戏逻辑贴图引用，
保留源引用，不伪装成本地文件。缺失声明/文件的本地资源必须报错，不留下半导入的材质或改动原槽。
同名文件从不同目录导入不得覆盖已有材质/贴图。
只读取静态 Material/Texture 声明，不把 Render/Key 的 if/endif 当作普通 INI 属性。
新导出的 `.mat` 带 `overrides=true`：它已是作者修改集，再导入时不会把其中的修改误记成原生基线。
离线完整材质没有此标记，未改属性仍从 source 复制；切换材质槽本身会生成对应材质声明和槽绑定。

这是 EFFMAT 文件导入，不是任意 Unity YAML .mat 或 Blender 节点图转换。
source 是 DLL 加载并复制的游戏材质逻辑路径；Shader 和原参数来自新文件，旧材质覆写项不自动混入。
手工改 source 不会从游戏实时发现参数，完整切换推荐导入对应 EFF .mat。

## 验收

测试自动新增键/原生不接管、无 UI 导出、稳定变量/状态编号、保存重开、增删重排、独立副本，
以及真实解析器/状态文件/重载、跨 Mod 隔离、坏文件、失败写入、默认值恢复；
材质测试跨包、同名资源、错误文件不改原槽、替换后增量导出和 DLL 材质构建接口。
自动测试、部署与游戏画面验收分别记录，不互相替代。
