# 2026-10-15：工作区索引与源包更新错误

## 已复现的三个问题

`E:/EIEM_Workspace/index` 的指纹与当前两层游戏 VFS 一致，但只有 2,117,479 条资产。逐 Bundle、逐记录对照发布的完整索引后，确定恰好缺少 1,864,548 条 GameObject；其他类型没有差异，两份索引均无重复。273,608 个 Bundle 的路径、实际内容 MD5 和长度都匹配当前游戏。因此这是同版本的受筛选索引，而不是旧版本资源。

根因是 GUI 默认将 GameObject 设置为可解析、不可导出，持久索引构建继承了该进程级设置。构建现在建立固定索引选项，并在成功、失败后恢复原界面选项。解析语义身份改为 `/2`，防止受筛选的旧索引继续通过同版本快速复用。索引记录格式和公共 gzip 包格式没有改变；公共包重新导入时会生成当前语义的本地辅助记录。

日志还记录了两处源包刷新失败：

- `materials/m_actor_lod_pelica_cloth_04.eff` 是独立材质源，没有 `prefab` 字段。原代码直接 GetProperty 抛异常。现在明确跳过、保留原包，并记录 `source-update-skipped.log`；这不表示已实现独立材质源的自动更新。
- `chr_0035_liino_postmodel.eff` 在备份旧目录的 Directory.Move 阶段被拒绝。内核句柄快照查到 Codex 持有其中 `materials` 目录的句柄。目录权限允许访问，Restart Manager 和进程工作目录检查未能识别这一目录句柄；隔离副本正常更新不能代替原目录验收。

源包发布仍优先整目录切换。若 Windows 返回目录占用/拒绝改名，且旧目录完整、尚未移入备份，则在同一来源 mutex 内完整复制备份，再对文件进行原子替换和退休，最后提交清单。失败按已修改路径逆序恢复；目录本身保留，兼容目录监视句柄。文件被真实占用时拒绝替换并回滚，不强制关闭外部句柄。更新日志保留完整异常与堆栈。
