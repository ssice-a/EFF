# 三端生产包审查

检查日期：2026-10-12。对象为当前工作区源码及本次构建的候选文件，不是既有 Git 标签的内容。未发布 Release、替换游戏 DLL、改写已安装 Mod 或保存用户工程。

结论：主要资源链路通过本轮自动验收，但正式发布前应处理发布来源绑定和兼容范围声明，整理失效的旧回归，并完成新构建的实机验收。以下明确区分实际发现的问题与尚未测量的范围。

## 发布前需要处理

1. **Blender 发布流程仍绑定旧框架标签。** `tools/Blender/.github/workflows/release.yml:15` 固定 `FRAMEWORK_TAG: v1.3.4`，第 61 行要求该框架标签中的 Blender 子模块提交等于插件发布提交。当前新增编辑器、动画及编译布局修改尚在工作区；直接为新插件打标签会因提交不匹配而停止发布。应先提交两个子仓库的全部必需文件，再由主仓库固定这些提交，创建配套框架标签，最后更新 Blender 发布流程的来源标签。不要移除提交一致性检查。

2. **两个代理 DLL 写死系统目录。** `src/proxy_vulkan_full.cpp:5` 和 `src/proxy_d3dcompiler.cpp:7` 的 PE 转发目标是 `C:\Windows\System32\…`，本次二进制检查确认该路径实际进入了导出表。Windows 装在其他目录的用户不能通过这条路径找到系统 DLL。发布前应使用实际系统目录的加载/转发实现，或明确将当前安装环境列为支持范围。Vulkan 代理还在进程启动时设置 RenderDoc/GfxTrace 禁用环境变量，并负责加载 `plugin/*.dll`，所以它并非只有函数转发；本轮没有发现它在每帧执行图形拦截。

3. **Blender 最低版本声明与二进制依赖范围不一致。** 两个入口的 `bl_info` 声明 Blender 3.0；当前安装包内 Pillow 的原生模块为 `cp311-win_amd64.pyd`。只验证了 Windows x64、Blender 5.0.1、Python 3.11；不同 Python ABI 不能直接使用该套原生模块。应收窄支持声明、提供明确的依赖检查，或为其他支持环境单独构建依赖。README 已注明不同 Python 布局需要配套依赖，但安装时的版本提示仍不一致。

4. **旧按键导出回归尚未迁移到现行格式。** `tools/Blender/test_eiem_switches.py:196` 用没有 `source/manifest.json` 的虚拟来源调用正式离线导出，实际在来源验证处失败；之后的断言仍期待 `[Render]`、`submesh_visible.*` 和合并为一个 Mesh 的旧输出。这是失效的验收夹具，不能据此判定当前按键功能坏了，也不能把该测试记为通过。需要改成现行 Part/Replace/compiled.bin 的集成测试；本轮现代按键路由及 DLL 按键/持久化回归通过。

5. **源码、发布说明和领域文档还没有完成收口。** `eiem_material_editor.py`、动画模块及多个编译索引头文件尚未被 Git 跟踪，`git commit -am` 不会收录它们。`CONTEXT.md` 仍有“物理快捷键限于所选 Mod”“真实游戏样本仍只有 LZY”等过时条目，与独立按键开关和当前四 Mod 状态矛盾。现有物理文字也应明确“新增链离线编译已接通”和“完整模拟/退出未全面实测”之间的区别。正式发布需从确定的提交构建，不能用本机完整工作区成功来证明标签源码完整。

## 性能实测与界限

- 同一已保存 Liino 工程，隔离副本中只改一个材质参数：源码插件 1.595 秒，独立候选安装包 2.133 秒。两次都写出 1 材质、0 Mesh、0 贴图，未进行贴图转换，62 个输入复用；63 个原生输入与完整重新编译逐项一致。所用参数为 `_AdvancedOption`，不代表任意新增材质或换 Shader 都能走同一快速分支。
- 当前四 Mod、201 个来源输入、16 个共享输入：独立新进程调用实际 `EiemCompiledModSet::Read`，墙钟 993.972 ms；随后未变集合读取 17.633 ms。没有启动游戏或调用 Unity，也没有清理操作系统文件缓存，因此不称为磁盘冷读或真实 F10 总耗时。
- 部分共享输入仍有对象合并/重定位。并行 worker 的 replay 合计 597.757 ms、共享对象合并合计 256.977 ms，与墙钟存在嵌套和并行关系，不能直接相加。当前结果仍没有达到“所有首次集合准备只花几毫秒”的目标。
- 视图逻辑长度 1039.51 MiB 不等于进程实际占用；视图可以共享原始文件/数据块，本轮没有把逻辑长度当成完整副本内存。
- DLL 没有每帧编译或全场景 Renderer 查询。按键轮询、受动画影响的形态键控制和加载/退休状态仍需帧回调；显隐只在控制值变化时处理，空闲弱引用清理分摊到帧。不能据此承诺每帧零成本。

## 实机验收尚未完成的范围

当前新的候选 DLL 没有在本轮替换或启动实机。自动回归不能代替冷启动、实际改资源后 F10、UI/大世界切换、NPC 默认/按键状态和多次 F10 后帧率/内存稳定性的画面与计量。
