# Blender 分资源导出

Blender 内的“导出所选 Mod”默认导出全部资源。选择已有 Mod 目录时可选择以下范围：

| 范围 | 写出内容 |
| --- | --- |
| 全部资源 | 所选网格、材质、贴图，以及切换、形态控制与选定 LOD 配置 |
| 仅 Mesh | 已有对应 Mesh 的几何、索引、骨骼路径、bindpose 和形态通道 |
| 仅材质与贴图 | 所选网格引用的材质增量、贴图，以及必要的 INI 声明 |
| 仅贴图 | 所选网格材质引用的 TEX（像素、mip 和规格）及必要的绑定声明 |

部分导出必须有已有的完整 Mod。未选中的资源、按键、形态控制、替换规则及 LOD 映射保留。新增或重命名部件、变更材质槽布局、删除受控形态通道需要全部导出。“全部资源”仍以选择内容为完整导出范围。

已有 Mod 按 INI 声明、资源字段、引用和校验和验证，不要求生成器注释保留在第一行。改名后无引用的旧资源直接移动到本次发布的临时回滚目录，避免先复制再移动同一文件；发布失败仍恢复原文件。

无需手动执行 PNG 转换器。Blender 自动读取图片并生成 `.tex`，随后调用插件自带编译器准备该 Mod 的 compiled.bin。游戏 DLL 不解码 PNG。

有形态键的 Mesh 导出保留完整 `m_Shapes` 与形态控制，顶点使用 Float32 position3/normal3/tangent4（首流 40 字节），骨骼槽、权重与 bindpose 一并写出。残影专用的形变快照由 DLL 捕获适配器在运行时生成，不能为了残影而在 Blender 导出端删除主 Mesh 的形态通道。2026-10-06 使用 Blender 5.0.1 对保存的 LZY 工程做隔离 body 导出，已检查两条形态通道、浮点布局和骨骼数据，并完成配套 v35 离线编译；工程、游戏 Mod 和游戏缓存未改动。这项验证不证明残影画面正确，证据见 `diagnostics/body-afterimage-review-20261006/blender-review.json`。

## 静态来源准备

2026-10-06 静态链路已同步游戏与 Blender，现有 LZY 的来源描述和完整候选已经生成，无需重新导出。真实静态消费者范围覆盖 46 个 Prefab，首次构建工作量大于历史两个根的性能样本；正式冷编译约 180 秒，同内容复用约 9–10 秒，游戏内迁移未计。下文历史换图性能不能直接用于此次完整覆盖。

每个 Mod 自动带有 `source-inputs.bin`。首次或来源身份变化时，导出端从原生来源工作区找到已有 AnimeStudio 索引，并在作者发布前调用配套静态工具。只改几何、像素、材质字段或按键且来源声明不变时复用描述，不重复读取全局索引。随后插件编译器只处理当前暂存 Mod；新增、删除和修改通过 F10 提交。索引无需安装到游戏，DLL 不解析或扫描全游戏资源。

当前全量导出会把上一发布的来源描述复制到独立暂存目录，再交给来源工具核验。此前全量导出创建空暂存，未提供旧描述，导致同来源重复解析。工具仍核验声明摘要及内容；新增目标或改变来源时正常重新解析，不跳过校验，也不改动上一发布。

2026-10-07 在用户当前 Blender 工程中隔离导出 15 Mesh、5 Material、11 Texture、6 个 Replace 规则，同内容重复导出的作者阶段为旧路径 21.481 秒、优化路径 4.852 / 4.859 秒；静态来源准备从 16.943 秒降至 0.413 / 0.389 秒。各轮作者文件和来源描述摘要一致。首次声明不匹配仍花费约 14.8 秒解析来源。这些数值**不含离线候选编译**，不能称为导出总耗时；没有保存用户工程或覆盖正式 Mod。12 项离线调用、10 项作者核心与 11 项发布回归通过，已在已打开的 Blender 中重载 Python 模块，下次启动也使用工作区 Junction 内的修改。

## 同路径贴图测试

1. 在游戏中观察当前模型。
2. 修改 Blender 材质引用的 PNG 内容，例如将 `G:\zmd\lzy\body.png` 改为同尺寸白色图片，保持路径不变。
3. 选中身体 Mesh，使用“导出所选 Mod”，选择“仅贴图”，输出父目录为 `D:\Hypergryph Launcher\games\Endfield Game\plugin\mods`，Mod 名为 `LZY`。
4. 等待 Blender 导出与离线编译完成后，在游戏中按配置的重载键（当前为 F10），观察身体贴图。

未绘制修改的文件图片直接读取最新磁盘字节，避免 Blender 已加载图片的旧像素缓存。正在 Blender 中绘制的 dirty 图片仍导出当前绘制缓冲。

新 Texture 声明不写 `source.*`，只写 `path` 和非默认的颜色解释/采样设置。TEX 内保存实际尺寸、RGBA32 格式和 mip 数；换用不同尺寸的 TEX 不需要修改 INI。首次更新旧格式会迁移这几个字段，此后只改像素或尺寸时，原来的 `.tex` 路径和 `mod.ini` 字节保持不变。

TEX 始终使用当前图片的文件名主体：`body.png` 写成 `textures/body.tex`。更新已有 Mod 时也会迁移旧哈希文件名、更新 INI 引用并清理无引用的旧 TEX，不再优先保留旧路径。不同文件名的图片即使像素一样也保留各自的 TEX 名。不同内容的图片若同名则报告命名冲突，需修改图片文件名；不会自动添加哈希或声明后缀。颜色解释、采样参数或材质绑定变化时会更新 INI。

## 性能及验收边界

贴图与材质模式不调用网格导出。离线编译复用几何、外观输入和已验证的命名修改位置；贴图模板解析直接使用已校验的输入，资源描述及材质依赖扫描按输入并行处理，最后按原顺序合并。所有输入仍执行完整校验并发布完整代际。Blender 在一次导出中只转换一次相同图片及采样设置，即使不同材质槽使用不同的原生贴图模板；各模板的来源身份和冲突检查独立保留。

| --- | ---: | ---: |
