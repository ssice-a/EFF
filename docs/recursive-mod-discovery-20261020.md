# 递归 Mod 发现（2026-10-20）

用户要求将独立特效包组织在已有角色 Mod 的子目录，例如 `plugin/mods/lx/petals/mod.ini`。现已让启动、F10 和 F9 共用的发现入口递归遍历目录，即使父目录已是一个 Mod 仍继续发现其下的独立包。分组目录可任意嵌套；点号目录和目录链接不扫描。

只改发现会让严格的资源清单校验把子包当作父包多余文件，因此同时增加了 C++/Python 的独立包边界。资源清单、父包内容证明和编译改动检测忽略子包；父包发布只替换自身声明的文件，部分导出的暂存复制也不复制子包。独立特效作为父包重新发布时保留其下子包。子包自身仍严格校验资源。完整路径用于目录区分，同名文件夹可以位于不同分组，Mod id 仍全局唯一。

验证：

- `mod_discovery_smoke`：Unicode、分组、父子同时发现、隐藏目录、稳定排序、同名目录、包资源边界、父包指纹和编译来源戳隔离；真实人物/特效读取、编译集合复用、嵌套角色路径重新定位通过。
- `effect_debug_smoke --disk-check`：F9 从角色子目录读取独立花瓣；无人物包的多层分组特效、失败后清空待发布候选通过；原特效生命周期/挂载回归通过。
- Python 目录契约 29 项、运行控制 4 项、Blender 导出核心 33 项通过；父子分别严格校验、人物发布保留子包文件、特效父包发布保留子包通过。
- 隔离 Blender：先导出子特效，再进行父人物的原生完整导出，子包文件逐字节一致。结果为 `bin/recursive-mods-20261020/blender-export-verified/report.json`。
- 编译集合已有组合回归、普通 v35 DLL 构建、生产二进制检查、独立进程加载和控制锁检查通过。新作者编译器包含此次包边界与之前的网格/贴图增量优化。

本地安装记录为 `bin/recursive-mods-20261020/deployment.json`，保留旧 DLL 和作者编译器备份。仅更新 DLL 与配套作者实现；协议数据布局不变，游戏 `eff.ini`、`package-protocol.json` 与全部 Mod 文件校验保持。当前 Blender 只更新纯 Python 导出回调，136 个对象设置、特效作者数据、材质绑定、选择及 12 项网格快照缓存保持，原 `.blend` 未保存。

新 DLL 在下次游戏启动生效。嵌套特效的挂载仍取决于其包内的来源 Renderer/骨骼和可见状态；目录层级不会自动绑定父角色。此次验证未启动游戏，不据离线成功宣称花瓣画面或实机 F9 性能已通过。
