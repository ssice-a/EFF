# 游戏目录与两层 VFS 索引

2026-10-13。AnimeStudio 的 Open Endfield VFS 支持游戏目录、上一级 games 目录、Endfield_Data 或已安装游戏的 VFS 子目录。只检查直接子目录中的 Endfield 安装，不递归搜索启动器临时目录；发现多个安装时要求明确选一份。独立 VFS 副本仍按单层打开。预下载的分卷 ZIP 和 CHK 差分不是已安装来源，不自动参与合并。

## 来源选择

- 按 BLC 的 directoryHash 与 version 选择当前块，较旧的 Persistent 块不覆盖较新的基础块；同版本内容冲突拒绝打开。当前块完整替换同身份旧块，不能将已从新块移除的旧条目补回。
- 当前 BLC 的记录与 CHK 位置分开：热更新目录的清单也列出基础层的 CHK。只有 CHK 内容身份一致，或者逐文件 MD5/长度与基础条目一致时，才允许从基础层提供对应字节。
- 新内容未下载齐时保留“不可读取”的状态，不能降级成不同内容的旧文件。当前机器合并清单有 12 个非 Bundle 资源缺少物理载荷；255842 个 Bundle 均有物理文件。缺少任意 Bundle 或解析失败时，索引构建拒绝发布当前成功索引。
- 修正旧路径解析将 `+` 等可打印字符截断的问题，避免不同逻辑名称碰撞。普通原包导出不再仅因目标同长度就跳过写入。

## 索引、缓存与编译器

有效身份为 `EFF_VFS_LAYERS_V1:<SHA256>`。输入包含两层 BLC/CHK 的相对路径、大小、修改时间及所有 BLC 的实际内容 SHA256。CHK 载荷不在身份检查时全量读取。基础目录与热更新目录出现、消失或变化均影响身份；目录自身时间、Mod 导出次数、预下载 ZIP 不作为游戏资源身份。

旧单层 eidx 不冒充合并索引。GUI 打开时自动准备当前索引：没有可信基线时完整构建，已有逐 Bundle 内容记录时增量更新；已完成且精确匹配当前两层身份的旧格式 3 索引可以直接迁移，不重新解析游戏 Bundle。CLI 导出拒绝尚未更新的旧身份索引。构建前后核验资源身份；更新发生于已打开窗口或构建期间时拒绝导出/发布，提示重新打开。Bundle 预览缓存继续按实际载荷 MD5 命名。

Blender 的原生来源编译器采用相同合并指纹与范围选择；先读取索引头核验当前两层身份，再决定是否复用 source-inputs.bin。来源描述身份包含资源目录身份，游戏更新后不能以“作者声明没变”直接复用旧候选。无变化时不重新遍历 eidx 全体资产。继承 runtime 新增 PFB 的单文件行为继续由已有 carryover 流程负责。

## 游戏更新后的增量索引

2026-10-13 新增逐 Bundle 增量构建。游戏身份不变时复用原索引，不重写；身份变化后先比较 BLC 中的逻辑路径、逐文件内容 MD5 和长度，未变 Bundle 直接复制已有资产与 CAB 依赖记录，仅新增或内容变化的 Bundle 读取载荷、解密并解析。CHK 所在层、文件名、范围变化且逻辑路径/内容未变时仍可复用。删除项从新索引中移除，不从旧基础层补回。

`endfield_assets.eidx` 仍使用原格式 3，Blender 编译器和已有 C#/C++ 来源 reader 无需改读法。同目录增加一个 `endfield_assets.eidx.bundles` 二进制文件，记录每 Bundle 的内容身份、索引记录范围、数量和 SHA256；不创建几十万个小文件，也不每次更新增加一个永久文件。解析语义身份与软件发布版本分开，升级软件但解析语义不变时继续复用。

完整且身份精确匹配的旧格式 3 索引可以读取一次紧凑索引来生成该文件，原 eidx 字节不改、游戏 Bundle 解析数为 0。旧游戏身份且没有逐包记录的索引不能冒充当前基线，需要建立一次可信基线。解析规则改变、索引范围损坏或增量记录不可用时重新处理受影响内容；单个已知范围 SHA 不符只重解析对应 Bundle。

更新仍要比较全部 Bundle 的目录记录，并顺序读取、校验与写出未变化的紧凑索引记录；这不是读取/解密全部游戏包，但也不是只写几个字节。保留单个完整 eidx 的代价是更新时的索引 I/O。本轮未改成追加式资产数据库，不能将小规模夹具的毫秒结果推断为全量目录固定耗时。

缺少当前载荷、解析失败、取消或构建期间游戏更新时，不发布不完整索引。成功进度保存可校验的记录前缀，失败 Bundle 不计入成功断点；同资源身份恢复断点，身份变化重新选择增量集合。复用路径减少检查点落盘和 UI 进度事件，避免处理几十万条记录时逐条刷新。工作区锁与进程内解析锁防止并发构建串用状态。
