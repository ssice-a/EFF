# 花瓣数量与预览差异（2026-10-21）

用户确认游戏内花瓣已显示，但更少、消失更快，方向与速度也不同。本轮比较当前 Blender 作者数据和已安装包的原生 ParticleSystem，并检查实际 GameAssembly 方法。

## 数量控制

原 Prefab 带有 `HG.Rendering.Runtime.VFXAutoEmissiveRate`，与挂载哪个角色无关。原生 `OnPlay → AppyValue` 将选中轴的缩放乘积乘脚本发射率，写入每秒发射曲线的 constantMax，同时设置粒子缩放方式、将容量限制到 1000；不改寿命和随机范围下界。当前单位缩放时，作者随机 10～18 因脚本值 4 变为 10～4。

新导入和 **设为持续发射** 现在默认关闭此规则，直接使用 **发射数量** 模块；不修改原来源或其他脚本。高级块 **按缩放自动计算数量** 可重新启用，编辑发射数、世界/局部缩放、粒子缩放方式和轴遮罩，预览会计入覆盖。开关保存为原生 UInt8 的 0/1。

其他已保存工程不会在打开面板时自动迁移；仍启用时可点 **使用下方的发射数量**。用户明确要求后，已对当前花瓣关闭该组件。原生基类 `VFXPlayableMonoBase.Play` 经 `Behaviour.get_isActiveAndEnabled` 检查，禁用后不执行该规则。

## 预览修正与限制

- 按骨骼保存的原生局部 TRS 与当前姿态计算挂载。Mesh 无修改器时通过唯一的原导入 ID 与骨架资源段关联，不按同名骨骼猜测；歧义拒绝导出。
- 速度沿生命周期积分并计入 speedModifier；世界速度/重力与局部运动分别变换，缩放按层级/节点/仅形状处理。
- 半圆弧同时限制出生采样与范围线框；关闭形状不应用保留的形状变换。
- 容量满时保留存活粒子、拒绝新出生，修复旧预览用最新粒子替换旧粒子的错误。

Noise 仍为近似摆动，轨道/径向运动未还原；`HGRP/Effect/VFXDitherAlpha` 的抖动透明仍为近似。面板明确提示，不保证这些效果与游戏一致。

当前已安装包与作者粒子字段相同：寿命随机 0.5～1.5 秒，simulationSpeed=1。Alpha 和大小随寿命下降，材质另有抖动透明。因此“消失快”需区分真正死亡、时间缩放和提前不可见。

普通 `eff.dll` 新增播放后、1 秒、3 秒的只读 `[EFFECT-PARAMETERS]` 采样：数量、系统时间/速度、Unity 时间缩放、寿命/初速度/发射率模式与范围、缩放和模拟空间；可用时读取最多 256 个活粒子的出生/剩余寿命和速度范围。失败不阻止播放，三次后不再轮询字段。没有新增 DLL、PID 或 Blender 热更新流程。

## 后续：出生即透明与容量限制

用户将寿命改为随机 6～10 秒后仍观察到出生即溶解。重新读取当前发布包确认寿命已是 6～10 秒；上文 0.5～1.5 秒仅描述此前快照。

实际 `HGRP/Effect/VFXDitherAlpha` 的已编译 DepthOnly 程序对透明度应用 `_DitherAlphaExp` 后抖动裁切。当前值 15 叠加从出生开始的线性 Alpha 下降，在寿命进度 10% 时透明覆盖已降至约 `0.9^15=20.6%`。独立溶解模块关闭，遮罩使用 R 通道，发布贴图 mip0 与作者 PNG 的 RGBA 字节相同。

同时，原生 `InitialModule.maxNumParticles=40` 会在粒子还活着但几乎不可见时阻止新粒子生成。每秒随机 10～18、寿命随机 6～10 的确定性离线采样，在提高容量后约有 110 个同时存活；这不是实机计数。

最终按用户要求关闭 `ColorModule.enabled`，取消颜色随生命周期及其中的 Alpha 渐隐；保留渐变数据以便重新启用。`_DitherAlphaExp` 改为 Shader 默认值 1，最大存活数提高至 200。寿命 6～10 秒、每秒发射 10～18、运动、大小、挂载和贴图保持。导出期间用户关闭自动随机种子，最终导出保留该选择。

当前 Live Blender 与隔离导出原生粒子字段完全匹配；19 个原生资源逐字段核验通过，除上述字段及 CAB 重命名外保持不变。纯特效更新耗时约 2.49 秒，已备份并发布到 `plugin/mods/lx`，仅替换特效资源和 `compiled.bin`，其余 328 个文件哈希不变。没有更换 DLL、保存 `.blend` 或启动游戏。证据：`bin/effect-material-audit-20261021/native-verification.json` 与 `deployment.json`。实际画面仍需进游戏检查；已有运行时只读参数采样因缺少 `MinMaxCurve.get_curveMultiplier` 精确签名而未完成，不把离线采样作为实机验证。
