# 独立 Mod 编译结果与资源契约

> 历史实现契约：描述现行旧式 `compiled.bin` / `compiled.blocks` 加载路线。新格式与资源组织以 [ADR-0001](adr/0001-authoritative-mod-directory.md) 为准；本文保留作迁移输入和行为对照，不应作为新 Mod 发布格式。

`mod.ini` 是唯一作者规则入口，独立 `.mesh/.mat/.tex` 是作者载荷。Blender 的配套工具生成 `source-inputs.bin` 和 `compiled.bin`；DLL 读取后者，不调用作者工具。兼容性依据 `eiem_package_protocol.h` 的实际字段与 `eiem_compiled_mod.h` 的结构声明判断，不按版本号。

## 输出布局

```text
YourMod/
  mod.ini
  source-inputs.bin
  compiled.bin
  meshes/*.mesh
  materials/*.mat
  textures/*.tex
  state.ini              # 游戏生成的玩家数值，可保留
```

`compiled.bin` 保存原生编码块的读取布局、对象表与等长命名位置、独立作者载荷引用、来源范围/摘要/离线文件标记、依赖编号、Prefab 装配与骨骼路径共享字典。运行索引和每个输入的对象证明分别压缩；普通读取不解压或解析对象证明，只有实际共享写入或来源恢复需要它。尾部 SHA256 覆盖整份编译结果。大型 Mesh 和贴图仍通过独立资源文件引用，不重复打包原版资源，也不设置容量上限。

当前 DLL 只接收 `native-view-index+assembly-dictionary+verified-source-stamps+per-input-proofs/le64/sha256` 字段布局；旧 `compiled.bin` 必须重新导出。没有旧编译包、旧 current.tsv 或独立 loading-inputs.tsv 的生产回退读取。此限制依据数据结构，不依据发行版本号。

原游戏相对路径在读取时绑定当前安装并校验范围/摘要。作者根重新绑定 Mod 当前目录；移动到另一安装不依赖作者机器绝对路径。来源更新、资源或替换声明变化需要重新导出。仅按键、数值、显隐、形态控制修改不改变编译资源契约，可由 F10 读取；源资源字节变化不可用旧编译规则。

## 编译与发布

Blender 在暂存目录写选中的作者资源，使用自身安装目录的 `eff_resource_pack.exe --export-mod <staged Mod> <game> --source-index <index>` 在同一进程中复用或更新来源描述并编译一个独立 Mod。作者侧解析 Mesh/材质/贴图、寻找消费者、生成对象、校验规则回放。全部成功后才发布该 Mod；失败不覆盖此前完整结果。其他 Mod 不参与这次作者编译。

来源查询直接读取现有 AnimeStudio 索引和相关游戏文件范围，包名在查询阶段复用，依赖边使用内部编号；VFS 元数据并行解析后按原文件顺序合并。构建阶段在同次导出中复用已验证和解码的原始包，不新增持久化原包缓存。索引与模板留在作者机器。游戏安装只含 DLL、代理、设置及字段声明。

## DLL 应用规则

启动和 F10 读取当前完整 0/1/N Mod 集合，校验作者资源契约。带原生读取布局的独占输入直接绑定离线生成的对象表、原始编码块范围和作者缓冲区；旧输出需要重新导出。共用输入合并已编译对象记录，对不同原对象保留各自修改，对共用 Transform、LOD/helper、AssetBundle preload 列表按原槽位合并，对新增流调整偏移。重复原 Mesh 目标或同一字段的冲突修改拒绝。没有重新生成几何、材质或贴图，也没有重新查找 Prefab 消费者。

原对象未被声明修改时保持原字节。删除 Mod 使用此前来源证明恢复 pristine 候选；空集合走同一事务。集合候选与作者文件完整核验后才提交，导出过程中变化的快照拒绝，失败保持当前运行时代际。

独占及只读输入直接绑定离线读取布局，不在 DLL 中解码或编码容器。来源使用受只读句柄保护的文件映射，匹配离线文件标记时不提前读取全量原版数据；标记变化时重新验证范围摘要。只有多个 Mod 实际写入同一输入时才按已编译对象证明合并，共用只读输入或只有一个写入者时不进入合并。作者提供的成员位置和命名重定位位置用于直接修改已验证的输入字节，切换命名空间不再重新解码、重放或编码整个输入，也不在 DLL 内压缩启动缓存。未改变的 Mod、来源证明和准备输入共享只读记录；改变集合时仍验证冲突和恢复 pristine 资源，不保存完整原包到 Mod 文件夹。

准备好的启动与隔离记录共用不可变字节所有权，按需恢复启动命名空间。游戏具备完整公开绑定时，使用只读 `UnmanagedMemoryStream` 读取 C++ 字节，流及其底层字节保留到异步请求完成、Bundle 原生对象退休后，避免再分配和复制同等大小的托管 Byte[]；绑定缺失时保留原 MemoryStream 路径。Unity 线程仍承担原生加载、核验和真正改变资源后的 owner 生命周期。启动入口已经发布的同一份资源不再预加载第二套隔离 Bundle；启动和热重载已经发布的相同资源再次 F10 只刷新控制和设置，仍预检作者文件与目录集合，不重新加载 Bundle 或重建角色。这不代表首次加载或改变 Mesh 后的 F10 已达到毫秒级。

DLL 不读取 `current.tsv` 或旧全量输入，不生成全局作者集合缓存、不启动编译器、不读取解包索引、不主动查询游戏来源。当前 Mod 必须提供配套作者端生成的编译结果。

验证边界见[热重载测试](hot-reload-testing.md)。离线回放/模拟事务通过不表示所有模型的实机画面已验收。

## 原生输入读取布局

字段 `native-encoded-block-spans+literal-name-sites/le64` 保存每个来源的编码字节区间、改写后的元数据、作者资源引用和等宽命名位置。当前编译结果必须包含该布局、离线摘要和运行索引；以字段声明确认兼容，不以应用版本选择。编译器及 DLL 的结构声明包含 `compiledInputView`，Blender 发布前核对实际字段支持。

作者端重写 SerializedFile 对象表：未改对象指向原包中的原始对象数据，新增/改写对象和流式数据提前排列；目录允许成员读取窗口覆盖同一原始数据区域。原始压缩块保持编码字节，不复制进 Mod、不在 DLL 中解压。等宽的集合代际命名仍在运行时应用到少量字面区间。Unity 通过注册读取视图的 Read/Seek/Length 回调读取，未注册的 Stream 直接调用原方法；空 MemoryStream 只作可读接口外壳。异步请求、Bundle 与读取数据共用明确的生命周期。

运行时仍绑定原范围和当前代际；来源文件标记变化时核验 SHA，实际多写入者共用输入时合并对象记录。物理/动画的实际游戏对象创建仍由 Unity 完成，不能表述为改变资源后的 F10 已达到毫秒级。当前安装的四个 Mod 使用新结构，体积及实测见[热重载测试](hot-reload-testing.md)。


## 离线与运行时边界（2026-10-12）

作者端生成启动视图摘要、展开后的 packed-frame 数据、完整依赖编号及原版装配描述。运行时共享这些不可变记录，复用已验证作者载荷；命名代际使用读取布局与改名位置的逻辑身份，不重新扫描整份虚拟输出求 SHA。普通游戏资源路径查找使用文件路径和偏移索引。

F10 的原生 Bundle 提交只覆盖当前已观察或显示根的隔离依赖。尚未出现的角色/NPC/UI 保留未来加载路由，在游戏真正请求时补齐对应输入；原版共享依赖继续由游戏持有。该选择不扫描全场景 Renderer，也不按角色名分类。原生对象加载、GPU 资源创建及角色动画/物理生命周期仍由游戏执行，不能离线生成运行中 Unity 对象。
