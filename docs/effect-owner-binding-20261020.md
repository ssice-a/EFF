# 特效明确部件绑定与模型实例渲染层

## 实机失败证据

用户已将花瓣 `428fc265c91642bab14c33719e961d7f` 成功追加到 `mods/lx/mod.ini`。
日志在模型完成后反复报告 `reload native reference array coverage/limit`，没有进入特效播放。
读取实际包确认挂载部件为 `PartS_actor_wulfa_cloth_01_lod0_1.002`，挂点为
`Root/Bip001/Bip001_Pelvis/Bip001_Spine`，控制默认开启。

同一来源衣服 Mesh 展开为四个 Part。`.002` 的作者骨骼列表含 147 项，遍历首先遇到的
`PartS_actor_wulfa_cloth_01_lod0_1` 含 145 项。旧匹配条件在特效已有明确 Part 时仍允许来源规则兜底，
于是收集全部同源 Part，再用第一个 Renderer 的 145 项骨骼校验 `.002` 的 147 项，导致拒绝。

证据快照与测试日志位于 `bin/effect-binding-fix-20261020/`。

## 修复

- 明确 Part 只匹配同包、同 Part 的原生 Mesh 标记；独立特效没有 Part 时继续按来源规则或原始网格证明匹配。
- 骨骼数量错误改报具体 Part、期望项数和实际项数。
- 挂载和播放日志增加 Part、实例来源、模型路径、层、粒子系统数量，便于区分加载入口与播放失败。
- 每个模型根独立绑定骨架、实例和显隐，原生 Bundle/Prefab 按内容共享；继续使用游戏的模型部件与 UIModelLoader 生命周期。
- Unity 子对象不会自动继承父物体的 `GameObject.layer`。创建克隆后、注册和启用前，将整棵特效克隆树的层设为可见挂载网格的层。
- 活跃时读取挂载网格层以跟随后续 UI 设置；层没变化不写，变化时仅更新缓存的本克隆子树，不进行场景扫描，也不重启发射。
- 创建失败后，候选明确交给退休队列并释放创建作用域的引用；失败注册的独立弱引用与 GC handle 清零检查通过。

NPC 和 UI 使用各自实例的真实骨架与可见网格，不使用玩家骨架或当前选中的 INS Mod 作为挂载对象。
适用范围是实际包含目标部件的模型实例；不同 NPC/LOD 若没有目标网格，不猜测替代挂点。
UI 原有光照和页面绑定仍由游戏负责，本次新增特效对其渲染层的跟随。

## 验证

直接包含生产入口的隔离测试先复现与实机一致的骨骼列表拒绝，再验证修复。新增三实例场景通过真实
`RecordPartFinished`、`RecordUIModel`、`PartReleased`、`UIUnload` 调用边界，覆盖：

1. 错误同源 Part 排在前面且骨骼数不同，仍只绑定明确 Part。
2. 世界角色、另一个模型部件实例（NPC）和 UI 实例使用各自挂点，拥有三个不同克隆，共享同一资源代际。
3. 隐藏挂载 Part 时，即使同源其他 Part 可见也停止对应特效，其他模型实例继续播放。
4. 注册和激活前，克隆根及子对象均已继承各自网格层；UI 后续从层 21 改为 22，不重建特效，不影响世界实例。
5. 不变层没有重复 setter；NPC 回收和 UI 卸载分别清理，不删除世界实例。
6. 原有原生准备/播放失败保留、异步取消、延迟销毁、工作线程隔离和材质参数动画回归通过；失败注册无孤立实例，最终 GC handle 清零。
7. 使用当前安装的 `lx` 包验证 F9 只读特效、递归独立包、失败候选取消等磁盘行为。

生产构建、PE 和真实 DLL 隔离加载及本地部署记录见同目录日志和 `deployment.json`。
本次测试不代替游戏画面验收；需重启游戏后分别观察世界、NPC 和角色 UI，再检查新的 BIND/READY/PLAY 或 GAP 日志。
现有花瓣包数据可以继续使用，无须重新导出，后续参数修改照常导出并按 F9。
