## 使用

1. 使用 EIEM 离线包导入已有共享 Rig。在 Rig 的编辑模式新增父子骨骼；
   不参与网格权重的物理骨骼同样可以导出。
   新增骨骼的 head 和父级决定节点位置，tail 方向与 roll 决定导出的局部旋转；显示长度本身不写成物理参数。
   源骨骼的 tail 表示游戏 Transform 局部 `+Y`，不保证指向子节点，不能为追求视觉连续而重算源骨 roll。
2. 在编辑模式或姿态模式选择连续骨链，至少两个节点。
   N → EIEM → **物理骨骼 → 新建 → 从所选骨骼新建物理链**。
   所选链顶端初始化为固定，其余所选节点初始化为运动，可在面板修改。
   作者文件不把未选择的子骨骼加入链；首版要求一个固定根和至少一个运动节点。原生 BoneCloth 会从根递归
   展开实际 Transform 层级，因此 DLL 将作者边界外的子分支根写入 IGNORE，保持作者节点集合。
   也可点击**复制所选骨链为新增物理链**：只复制所选连续树的静止层级，根接回原外部父级，所有副本明确标为
   新增 Skeleton 节点。工具不自动复制网格权重；用户把需要运动的顶点权重转给副本，避免原骨与副本双重影响。
   之后在同一父链下加骨骼时，保持该组为**当前组**，选中新增后代并展开**链与碰撞体**，点击
   **将所选骨骼加入当前链**。每个根分支内部必须连续；多个独立根可放在同一物理组并共享参数与碰撞集合，
   需要不同参数时才拆成不同物理组。创建、加入和移除会立即
   重建实体预览，静止骨架变换在退出编辑模式后自动刷新；新增骨骼不会仅因靠近旧链而被静默纳入。
3. 选中物理组 Empty，在**对象属性 → EIEM 物理参数**中设置参数和“节点基础半径”。从游戏源组粘贴后，
   复制来的完整字段在折叠的只读“源数据检查”中核对，日常参数只在固定顺序的主界面修改。启用位置曲线后，
   设置根端倍率、末端倍率和线性/平滑变化；需要局部变化时展开“高级关键点”，以 0～1 链位置和倍率精确编辑。
   根端与末端不可删除，中间点可增删；半径球和角度锥会自动刷新。
4. 先在 Rig 上选择独立碰撞体的绑定骨骼，然后在面板添加球体或胶囊。
   用位移/旋转工具编辑骨骼局部变换；胶囊可分别设置首端/末端半径、两端球心间距和中心对齐方式。
   对象缩放、增量变换和额外约束在导出时拒绝，避免显示与文件不一致。
5. **当前组**指定共享引用的目标。选择已有碰撞体，点击**加入当前物理组**；
   面板列出所有引用组。**复制物理组**生成新身份、复制参数，并保留共享碰撞引用。
   不使用 Blender 的对象复制来创建新物理身份。
6. 选中要输出的物理组对象，点击**导出所选物理组**，指定新的 `.physics` 文件。
   只包含所选组及其引用的碰撞体；完整共享骨架自动作为依赖输出。
   两个不同 Rig 的组不能导出到同一文件。此入口与 Mesh 的选择/相机/skip 规则独立。
7. 保存 `.blend` 继续编辑。导入 `.physics` 时，如果当前选中相同的 EIEM Rig，
   校验完整节点/姿态/来源标志后复用；否则创建独立 Rig。
   同一 Rig 上重复导入相同身份会报错，不合并或覆盖原组。
8. 需要生成可加载 Mod 时，在物体模式选中目标 Mesh，点击**导出所选 mod**。可以同时显式选中作者物理组；
   若 Mesh 已对该组节点骨骼刷有正权重，插件也会自动推导该依赖，避免覆盖旧包时意外删掉 Physics。
   解析出的组自动带入共享 Skeleton，并绑定到所有使用该 Rig 的所选 Render。作者球体/胶囊及已引用的原生
   球体/胶囊会进入 v5；原生无限平面、原生 v2 组及没有同 Rig 可见 Mesh 的组仍不能进入组合 Mod。

源骨骼路径保持来源身份；新增骨骼通过独立作者身份关联，改显示名后导出当前完整路径。
删除引用骨骼会报错，不改绑到根或同名骨骼。编辑绑定姿态后可用**刷新骨骼绑定**；
**绑定到 Rig 的活动骨骼**显式修改碰撞锚点。

使用**删除碰撞体及全部引用**可同时移除辅助显示及所有组引用，操作支持 Blender Undo。
普通 Blender Delete 若留下失效组引用，导出会指出该引用；可在组列表中移除。
辅助体的显隐与游戏启停无关，不生成替换 Mesh 或 skip。

## 资源范围

- 原生后端标识为 `BeyondDynamicBone`，用途明确写为 `authoring`。
- 基础参数包含 `gravity`、`stablizationTimeAfterReset`、`gravityFalloff`、
  `blendWeight`、`animationPoseRatio` 五个标量。节点半径另存一份 `CurveSerializeData` 等价作者记录：
  `value`、`useCurve`、关键帧时间/倍率/进入与离开切线/加权模式/权重。未粘贴模板时使用插件作者默认值，**不是源游戏值**。
- v4 的 `nativeParameters` 可保存原生组全部可编辑数值、布尔/枚举和九类曲线；不保存 `sourceRenderers`、
  `paintMaps`、`rootBones`、`ignoreFromRootBones`、碰撞体引用、预构建字节或 `verificationResult`。
  因此它是新增链的完整参数模板，不是原始 BeyondBoneCloth 组件字节与引用图的无损往返；后者仍由源作者 v2 负责。
- 节点角色为作者层 `FIXED/MOVE/IGNORE`，不是原生 VertexAttribute 的位值，
  文件节点序也不是 setupIndex、Mesh palette 或 Animator 写回槽。
- 球体保存半径；胶囊沿自身 Unity 局部 Y 轴保存首端半径、末端半径与两端球心距离 `span`。
  DLL 调用原生 `SetSize(startRadius, endRadius, span + startRadius + endRadius)`。关闭中心对齐时首端球心
  位于碰撞物体原点；开启时由原生居中公式放置两端。v5 校验会拒绝原生居中公式无法精确表示的极端异径尺寸。
- Blender 辅助体通过 Child Of 约束跟随 Rig；原骨骼的源 TRS 缩放参与绑定补偿。
  这里只显示作者几何，没有 Blender 物理模拟。

文件通过完整路径引用骨骼，通过作者 UUID 引用组/共享碰撞体，不保存 Unity 指针、
team ID、Transform 实例 ID 或运行时任务状态。

## 二进制契约

均为 little-endian。字符串使用 **u32 字节长度 + 严格 UTF-8**，与现有 Skeleton 的
7-bit 字符串长度编码不同；长度最多 4096 字节。文件最多 16 MiB，不接受尾随数据。

| 顺序 | 内容 |
|---|---|
| 头部 | 8 字节 `EIEPHYS\0`；u32 版本 `5`（读取器仍接受版本 1/3/4） |
| 5 个字符串 | `authoring`、`unity-y-up-left-handed`、`BeyondDynamicBone`、资源 UUID、Skeleton 相对文件路径 |
| 碰撞体列表 | u32 数量，最多 4096 |
| 每个碰撞体 | id/name/bone 三个字符串；u8 shape（0 球、1 胶囊）；float32 position[3]、rotation[4]（xyzw）、startRadius、endRadius、span；u8 alignedOnCenter |
| 组列表 | u32 数量，1～1024 |
| 每个组 | id/name；u32 节点数，2～16384；各节点 bone 字符串 + u8 role（0 固定、1 运动、2 忽略） |
| 组参数 | float32[5]，按上面列出的参数名称顺序 |
| v3/v4/v5 节点半径 | float32 基础值；u8 useCurve；u32 关键帧数（2～64）；每帧 `4×float32 + u32 weightedMode + 2×float32`；最后为 3×int32 曲线元数据 |
| v4/v5 原生参数 | u32 数量（最多 4096）；每项为字段路径字符串、u8 floating；浮点值为 float32，整数/布尔/枚举为 int32 |
| 组碰撞引用 | u32 数量，最多 4096；各引用为碰撞体 UUID 字符串 |

所有身份为 32 位小写十六进制作者 UUID。组与碰撞体身份不重复；重复名称允许。
关键帧时间限制在 0～1并严格递增；原生数据的首末帧不要求恰好等于 0/1，倍率非负，权重限制在 0～1。
校验拒绝未知版本、非法数值/姿态、断链、缺失/重复引用和未被所选组引用的碰撞体。
Python 编码器拒绝额外字段，不能通过静默丢字段把其他 schema 伪装为作者格式。

Skeleton 存在相邻 `skeletons/<完整SHA256>.skeleton`，包含同一 Rig 的全部源/新增节点。
校验与序列化先在临时目录完成，随后先发布按内容命名的 Skeleton，最后原子替换 `.physics`。
失败不会先清空已存在的 Physics 文件；旧依赖保留，不递归删除用户目录。
不同版本导出留下的旧 Skeleton 文件不会自动清理。
