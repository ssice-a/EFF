## 问题与实现

PID 628 的 02:53:28 F10 提交第 2 代成功，03:05:53、03:06:13、03:06:19 均在候选加载后因 `reload model part load ownership was not recorded` 拒绝，保留第 2 代。该日志没有被拒绝部件的身份，不能将具体实例唯一归因于静态调查发现的入口。

当前游戏 `BaseModelComponent._LoadMainModelInternal(bool, System.Action)` 内联了释放、配置与加载流程，绕开外层 `BaseModelViewPart.LoadModel` 的登记作用域。原 `ReleaseModel` 观察器因此可能删除仍在加载的主部件记录，完成后重建的记录又没有 owner。以原生组件的 `m_mainPart` 关系为依据，内部加载事务现有独立线程作用域；释放时只保留实际属于该组件的主部件，支持入口已有部件与调用中创建部件。独立释放仍删除记录。

内部完成回调是普通 `System.Action`，不用于推断模型所有者。原函数完整转发 callback 与 MethodInfo，调用一次，原异常继续传播。归属缺失拒绝信息补充路径、部件类型和 rootId，便于识别尚未覆盖的其他入口。

此前未安装候选的内部参数绑定和原函数异常重试存在问题，已在本次修正；不能将旧候选当作已完成修复。源逻辑路径重新定位、只读末端依赖裁剪、原生资源加载及按需候选加载逻辑未修改。没有加入逐帧 owner 扫描或额外 Bundle 加载。
