# 统一动画基础修补与游戏会话检查

2026-11-17。本轮未提交、推送或发布 Release。保留此前工作区改动。

## 本轮修正

一条 EFF Action 继续持有统一的播放时间、速度、按键和暂停/停止状态。形态键、材质、作者挂点是接收输出的 Adapter；不新增分类型播放器。

1. `eiem_entry_animation_frame.h` 集中实际 Unity 帧执行顺序：控制输入与代际发布之后推进一次时间，再应用材质、形态键、特效绑定和作者挂点。特效绑定可能新建挂点，因此同一帧最后对作者节点采样。删除了 reload 维护函数里提前进行的挂点采样与特效更新。
2. `Player::RetainCompatible` 按 Action 迁移播放状态。增删或修改另一条 Action 不再重置整包动画；兼容 Action 保留时间、暂停和用户停止状态。新图重新建立冲突/所有权索引，不复制旧索引或旧样本租约。修改样本、目标、时长、循环或原生 Clip 修订会使该 Action 按新声明初始化。保留的用户播放优先于新增的冲突 autoplay。
3. 混合 Action 中，数值样本没有活动 Mesh 使用者时，不再冻结同 Action 的原生挂点时间。数值文件仍保持按需打开；使用者后来加入时接上当前相位，最后使用者退休后删除数值输出/租约。
4. Blender 从同一个原生 Action 分次添加多个 owner 时，复用一个 EFF 组。绑定、导出沿用实际曲线与实际选中资源依赖，不要求人工重建通道表。
5. Blender 的场景组身份与原 INI ID 分开。每次 Mod 导入共享一份场景映射，Shape/Material/Bone/Empty 使用同一映射；不同 Mod 的同名 Action 不再串组或互相同步速度。单独导出保留原 INI ID、速度变量和按键。主动把两个独立同 ID 组导出到同一 Mod 时给出明确冲突，避免静默合并。映射为内部作者元数据，INI 不增加哈希或二进制字段。

## 骨骼支持的实际范围

统一控制/时钟/冲突/热重载可以继续复用到骨骼通道；这不等于已经完成任意作者骨架的生产装配。

- 当前数值 Bone TRS 能导出、读取及统一求值，生产代码尚无 `boneOutput` 的 Transform 写入 Adapter。
- 当前静态武器的原生 `MeshRenderer` 不会自动转换为作者蒙皮 Renderer，也不会创建独立作者骨架。
- 作者 Empty 的原生 Clip 已有绑定/共享/退休链路，目前挂点树仍由特效使用者持有。无特效的模型骨架/节点需增加明确的模型 owner 绑定。
- 后续应补原生作者骨架装配、精确实例绑定和统一 Clip 输出，沿用现有播放与生命周期。按 [原生动画验证](native-animation-clip-validation.md) 的方向推进，不另建一个写游戏原始骨骼的逐帧播放器。
