# 形态动画与播放控制设计

2026-10-13。第一版已实现，Blender 面板、配套离线编译器和游戏性能测量 DLL 已本地安装。形态动画在 N → EFF 中独立于网格切换，播放组控制一组形态频道，动画随 Mesh 导出；Ins 面板允许实时调整播放速度倍率。构建、Blender 与隔离编译回归通过，游戏内动画显示及其实际帧耗时仍待验收；没有发布示例 Mod，也没有保存用户工程。

## Blender 作者流程

1. 选中 Mesh，在形态键的 value 上插入关键帧；动画来源是 Shape Keys 数据块的 Action，而不是 Object 的位置/旋转 Action。
2. 在“形态动画”点击“从选中网格动画创建播放组”，为每个选中 Mesh 读取其 Shape Keys Action 与有效 slot，自动选中其中有权重曲线的形态频道。同组使用一个稳定身份；范围取成员动作范围的并集。允许用户逐网格取消频道或明确选择另一个兼容 Action。
3. 显示动作名称、参与频道、帧范围与计算出的秒数；默认使用动作范围，也可手动指定。Blender 5 的 Action/slot 必须按真实所属数据读取，不能直接取任意 action.slots[0]。
4. 默认快捷键行为是播放/停止，循环开启、自动播放关闭、速度 1.0x；录制快捷键后提供插件预览和停止。创建多个片段时分别命名并保存引用，不能因切换当前 Action 丢失已配置片段。
5. 全部资源与仅 Mesh 导出同时带上动画；仅材质/贴图更新保留已有动画。形态增量只保存一份，多个动作引用同一 Mesh 频道。动画曲线和控制配置不应导致重复复制整个几何载荷。

多个频道可组成同一动作，例如翅膀展开、收拢和抖动，共用一个播放时间。同一网格和频道可用于多个组；不同频道可并行，重叠频道采用新启动组替换旧组，暂停组也被替换。尚未实现动作混合、交叉渐变或一键轮换。NLA 与驱动器必须先烘焙为独立 Shape Keys Action；运行时不解释 Blender 控制系统。

## Blender 面板

N → EFF 中“网格切换”管理可见物体；“形态动画”管理时间片段，两者使用相同的快捷键录制和列表交互，但不把动画塞入款式集合。

统一面板展示工程内全部播放组（名称、成员数、按键），没有活动网格时仍可管理。点击组名后在同一面板逐网格展开 Action/slot 与频道，并编辑共用范围、按键、循环及自动播放，预览/停止作用于全组。成员支持加入选中网格、选中物体、移出与选中全部成员。“更多设置”提供作者默认速度和离线采样率（默认 60Hz）。快捷键固定为播放/停止；停止后恢复手动权重，暂停保留当前动画姿态。

给成员形态键 value 插入关键帧后多选创建组，再逐网格勾选参与频道、录制快捷键；选择另一个 Action 时明确选择其 KEY slot 并点击“读取动作频道”。面板选择的组独立于当前活动物体，频道读取和 slot 操作显式指向成员。插件预览使用一个临时 Action 的多个 KEY slot，只含各成员勾选频道，停止后恢复所有成员原 Action/slot、当前帧、范围和权重；预览先验证全部成员，避免部分改写，不会保存工程。

## Ins 播放控件

选定 Mod 后增加“形态动画”区域，每个播放组显示名字、播放/暂停/停止状态、速度倍率与恢复作者默认按钮。

- Blender 设置作者默认倍率，默认为 1.0x。Ins 调整该组的实际倍率；避免把两个看似相同的倍率隐式相乘。
- 支持常用范围的滑块与直接输入数值；0.5x 是半速，2.0x 是两倍速。倍率必须是有限正数，暂停由独立按钮表达，不把 0 当作停止或负数当作反向播放。
- 调整立即生效，无需 F10 或再次导出，不重置当前时间；下一帧按照新倍率推进，不能用“开始以来的总时间 × 当前倍率”计算而产生跳帧。
- 播放速度按 Mod 身份和播放组稳定 ID 保存为玩家偏好，重启恢复；提供恢复作者默认。导出配置和动画曲线不被 Ins 改写。
- Ins 打开时暂停物理快捷键采样的触发，保留既有输入规则；动画继续播放，便于观察速度修改。面板通过不可变快照和命令队列操作，Unity 线程按当前代际验证目标后应用，不从 UI 线程调用 Unity。

## 频道控制与性能

播放只接管已选频道，其他频道保留手动控制。停止后恢复手动值，非循环动作到达结尾也会停止；手动滑块/形态快捷键操作先停止关联播放组，再执行用户操作。控制准备时一次建立频道到组的冲突索引；开始播放只停止索引中正在播放或暂停的冲突组，不扫描 Mesh 或在每帧重算组交集。停止不活动的旧组不删除新组输出。F10 成功提交后重建播放状态：初始自动播放的组从头开始，其余停止；有效的玩家倍率仍保留。同频道自动播放组按稳定 ID 顺序启动，最后启动者生效。

沿用当前同一 Mod 的多实例共享控制语义：每个活跃播放组每帧计算一次曲线，实例按绑定收到结果，新实例同步当前进度。时间以导出时记录的场景 FPS 和范围换算成秒，避免把游戏帧率当作动画采样率。

动画瞬时权重与播放进度不进入持久化变量写回，也不每帧刷新面板完整快照或日志。仅用户调整倍率或稳定偏好时批量保存。曲线采样、必要的约束烘焙、压缩和身份校验离线进行；每帧只推进播放状态、插值活跃频道并写入对应形态权重。仍需测量多组、多频道、多实例及 Capture 快照的实际成本。

## 文件与导出边界

`[ShapeAnimation<ID>]` 引用 `resources/shape_animation_<ID>.bin`。kind=8 的独立资源保存 Mod/播放组身份、名称、快捷键、时长、循环/自动播放、默认倍率及各形态变量的均匀 float32 样本，不重复嵌入 Mesh 增量。`$anim_speed_<ID>` 是持久化玩家倍率变量；手动权重和动画输出分别保存，播放不会逐帧改写 `state.ini`。

全部资源与仅 Mesh 导出会采样和更新动画。仅材质/贴图导出保留动画声明与字节。删除或禁用播放组后通过仅 Mesh 更新可清理旧片段和作者速度声明；一个播放组跨多个已发布部件时必须选齐，防止部分更新留下不完整的频道。部分导出不改变已有形态绑定范围；移除已绑定形态仍需要全部资源导出。

Python/C++ 均验证资源结构、身份、时长/倍率、采样有限性、频道与控制范围；动画必须通过自己的 ShapeAnimation 声明加载，倍率变量不能复用形态变量或另一个组的倍率。动画字节结构仍为 `sampled-shape-weight-clips/le32/1`；新增 `shapeAnimationPlayback=shared-channel-groups/replace-conflicting-playback` 声明共享频道的播放语义，旧编译器或 DLL 未声明时新插件阻止动画发布并保留旧 Mod。

当前只控制既有原生形态权重，不增加骨骼动画播放或自定义骨架控制。现有 `.eanim` 是游戏面部骨骼动画导入入口，和此处的 Shape Keys 动画分开。原有多帧形态及静态 Renderer 限制仍然适用。
